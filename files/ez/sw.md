# 凌动开关(PD)检测 — 中断化改造与日志解析

> 代码基线：`C:\Si\ws\ez01_matter`  
> 硬件事实：PB0 有电 = 50/60Hz、**占空比 ~50%** 方波（高 10ms/8.33ms）；  
> **凌动按下 = 恒低**；**市电断电 = PB0 立即恒低**（大电容只保 MCU 不保检测信号）；**上电方波恢复**  

---

## 0. 信号模型

```
AC 正常     ┌───┐   ┌───┐   ┌───┐   50/60Hz，占空比 ~50%
凌动按下    ─────────────────────   恒低
松手        ┌───┐   ┌───┐           方波恢复
市电断电    ─────────────────────   立即恒低（大电容只维持 MCU，不维持检测信号）
来电        ┌───┐   ┌───┐           方波恢复
```

关键事实：**"凌动按下"和"市电断电"在 PB0 上同构**（都是恒低），唯一区别是持续时间/是否松手，由时间区分，按下T < 1.8s 正常按下，T>1.8s判断为断电，前面响应一次按下已执行要取反处理。

## 1. 当前架构（中断层 + 原状态机）

改造原则：**必须中断检测、最小资源改动；`PdEventHandler` 的按下/松开/1.8s 纠错逻辑一行不动**。

```
PB0 双边沿中断 ──► ISR 测高电平宽度 ──► 窗口[7,12]ms 内 ──► 刷新"有电"标记(时间戳)
 (INT0/GPIO_EVEN)    (sl_sleeptimer)     窗外: short/long 计数, 不刷新

12ms PdEventHandler(原逻辑不动) ──► app_btn_mgr_btn_is_pressed() 过滤态:
   1=有电: 最近30ms内有有效脉冲(30ms > 一个市电周期20ms, 跨低半周不闪断)
   0=按下/断电: 标记过期或从未有过
```

- **ISR**（`app_btn_mgr.cpp::_pd_gpio_irq_cb`）：上升沿记时间戳；下降沿测宽度，落窗 → `s_pd_valid_tick` 刷新 + `ac_seen=1`；<7ms `short_cnt++`，>12ms `long_cnt++`，均不判有电（>12ms 是市电衰减畸变，判有电会断电误开灯）。
- **过滤态**（`app_btn_mgr_btn_is_pressed()`）分级：
  1. 中断注册失败（`irq_ok=0`）→ 回退旧直读；
  2. 边沿速率锁 v2：每检查周期(12ms)边沿 >100 **且**（开机宽限过后仍无有效脉冲 **或** 有效脉冲已停 >2s）→ 才判悬空/断线，关中断锁定空闲（log `PD noise lock: … valid never/stale …`）。强干扰叠加在有市电的线上时有效脉冲每 20ms 刷新 → **不锁**，窗口滤波自身拦截杂波。锁定后每 1s 解锁复查（log `PD noise unlock retry`），来电/松手可恢复。分析与依据见 §6；
  3. `ac_seen` 且 30ms 内有有效脉冲 → 1（有电）；
  4. `ac_seen` 但已过期 → 0（按下/断电）；
  5. 开机宽限 200ms 内裸读（等首个有效脉冲）；
  6. 始终无有效脉冲 → 1（无检测信号，空闲；USB 裸板调试场景）。
- **按下确认** = 30ms 标记过期 + 原 `low_count>=12`（≈140ms）→ 实际 **150~180ms**（近似原 150ms 规格）。
- **松手/来电** = 第一个有效脉冲 → 走原 `high_count>=3` 路径，延迟 ≈ 一个周期 + 36ms。
- **`PdEventHandler` 1.8s 纠错**（`event_count>=150`、盲 toggle 翻转）**原样保留**，仅数据源换过滤态 + 增加 PD 日志。
- **工厂复位前停 PD 定时器**（`AppTask::PdTimerStop()`，在 `app_frst_mgr.cpp` 两处复位入口调用）：复位期间平台任务持栈锁做 NVM3 批量擦除 ~2.4s，AppTask 队列停摆，否则 PD 每 12ms PostEvent 溢出刷屏 `Failed to post event`（旧固件就有，PD 日志放大）。

**中断注册**：`sl_gpio_configure_external_interrupt(双边沿, int_no=-1 自动分配)`；SDK `sl_gpio.c` 已定义 `GPIO_EVEN_IRQHandler`，不可自定义；PB0=pin0→INT0，工程内唯一使用者。

## 2. 相比旧轮询方案：修了什么、保留了什么

### 2.1 已修复（中断层带来）

| 旧问题 | 修复方式 |
|---|---|
| 队列积压 burst 读瞬态电平，`low_count` 一次跳满 12 → 假按下（防抖被压缩到 20~30ms） | 积压时读到的是同一份过滤态；低半周因 30ms sticky 仍是"有电"，瞬态低不再放大 |
| 衰减期杂波瞬时高电平清 `release_flag` → **取消 1.8s 超时**，NVM3 停错误值 | 出窗杂波不刷新"有电"，超时可靠触发 |
| 12ms 轮询相位与市电锁相隐患（改周期即无限误触发） | 边沿由中断独立打戳，与轮询周期无关；周期只影响确认延迟 |
| 60Hz 窄高脉冲被 12ms 采样漏掉 | 中断必见每个边沿 |
| 悬空引脚拾噪假按下（USB 裸板台架，~90kHz 噪声 18 万边沿/秒） | 宽限限时 200ms + 边沿速率锁 |

### 2.2 保留的已知取舍（用户决定保留 1.8s 逻辑，均未改）

1. **短断电（150ms~1.9s）双向翻状态**：灯开着断电 <1.9s 来电 → 灯灭；灯关着断电后来电 → 灯亮。物理上与按键同构，1.8s 纠错覆盖不到。
2. **超时按处理次数计时**（`event_count` 非墙钟）：AppTask 忙时超时被拉长，侵蚀电容余量。`PD timeout: actual=…` 日志就是量这个的。
3. **超时盲 toggle**：1.8s 内 APP/遥控改过 OnOff，翻回错误值。
4. **断电期间写两次 NVM3**（140ms 写 OFF + 1.758s 写 ON），都在电容余量最小窗口。

> 备选方案（未实施）：**"松手提交"**——按下只临时关 PWM 不写 NVM3，松手按低电平持续时长（<T_PRESS_MAX ≈600~800ms）决定提交翻转还是撤销恢复；断电零 NVM3 写入，1.8s 超时可删。需 PD 日志积累 `low_dur` 分布定 T_PRESS_MAX 后再评估。

### 2.3 不变的注意点

- **`high_count` 是跨周期累计语义，不能改成"连续 3 次"**，否则松手可能永不确认。
- **PD 定时器周期勿乱改**：改大要同步放大 `PD_NOISE_EDGES_CHK`（如周期 1s 时 50Hz 每周期 ~100 边沿会误触 noise lock）；改小无碍（只影响确认延迟）。
- noise lock 锁死至重启：~~极端 EMI 误锁时墙开关失效~~ → **v2 已加 1s 解锁重试**（§6），且强干扰+有效脉冲场景不再锁；残留：持续干扰下的断线要等 2s 才锁（断线头 2s 内 `is_pressed=0`，可能一次假按下确认）。

## 3. 日志解析

### 3.1 `PD press:`（按下确认瞬间，flag1 分支打印）

```
PD press: ev=%lu dt=%lums | edge=%lu S=%lu L=%lu w=%lums irq=%u
```

| 字段 | 含义 | 正常值 / 判读 |
|---|---|---|
| `ev` | PdEventHandler 处理计数，自上次清零（上次按下确认或 1.8s 超时） | 首次按下 = 开机以来累计，很大属正常 |
| `dt` | 距上次按下确认的墙钟 ms | 首次 ≈ 开机时长；之后 = 按键间隔 |
| `edge` | ISR 总边沿数（累计） | 50Hz≈100/s、60Hz≈120/s；两次按下间增量缺口 ÷200 ≈ 中间按住秒数 |
| `S` | <7ms 毛刺累计 | 台架 0~18/s（渐变/无线耦合时偏多） |
| `L` | >12ms 计数累计 | 1~3/s；**突发 10+** 注意电网干扰 |
| `w` | 按下瞬间最近完成的脉宽 | ⚠ 多为**被按下截断的脉冲**（0ms=按在高电平起点）。**真实市电脉宽看 `PD release` 的 w**（应 8~10ms） |
| `irq` | 1=中断生效；0=回退直读 | 必须为 1；为 0 查 `PD irq FAIL` |

**内置探针**：

1. **采样健康度**：`ev × 11.72ms ≈ dt` → 健康；`<<` → AppTask 积压（渐变/日志/复位窗口期出现属正常）。实测：`ev=1486 dt=17707ms` → 11.92ms/tick ✓。
2. **按键时长反推**：两次 press 间 edge 增量缺口 ÷200 = 按住秒数。

**异常模式**：S/L 持续大涨+功能正常 = EMI 被窗口拦截（无害）；w 恒 0 + S/L 冻结 + 随后 `PD noise lock` = 检测线悬空；`irq=0` = INT0 冲突/注册失败；dt 大但中间确有按键 = 短按 <150ms 被滤（规格内）。

### 3.2 `PD hb:`（每 1s 一条，尾部节流打印）

```
PD hb: dEdge=%lu dS=%lu dL=%lu dM=%lu hi=%lu/%lu win=%lu
```

⚠ **开机第一条是开机以来累计，不是 1 秒增量**（`hb_ms` 基线为 0）；之后每条 = 相对上一条的增量。

| 字段 | 含义 | 健康参考（每秒） | 异常判读 |
|---|---|---|---|
| `dEdge` | 边沿增量（中断调用数，含折叠） | 干净 50Hz ≈100~105，60Hz ≈120；flood 台架 180~460 | 持续 0 且无按键无锁 = **信号丢失/断线** |
| `dS` | <7ms 毛刺增量 | 0~2 干净；几十 = 有干扰 | 只增不减属正常，无功能影响 |
| `dL` | >12ms 增量 | **应恒为 0**（配对守卫后伪测量改道 dM） | 常态 >0 = 干扰形态转"漂高+dip 型"，守卫会漏，⚠ |
| `dM` | 配对完整性丢弃数（diff≠1 的折叠伪测量） | 干扰烈度直读表；**按压期间爆发 = 正常**（毛刺被正确丢弃） | 纯监控，无可行动阈值 |
| `hi=n/N` | 裸读电平占空：每秒 N 次点采样中 n 次读到高（12ms timer 轮询采样） | **有电 ≈ 40/86（方波约半高）；按下 ≈ 0~8/86** | **恒 0 = 无信号/断线；恒 1 = 接线/极性错**——"到底有没有市电信号"一眼可判 |
| `win` | 64 样本滑动窗（≈0.75s）内高电平数 = **存活判定依据**（§7.7） | 有电 27~30；悬空/断线 = 0 → 204ms 自动锁 | ≥3 判活：不锁 + 检测走裸读回退 |

**判读**：稳定 100~105 = 健康 50Hz；~120 = 60Hz；突降/0 且与 flag1 对齐 = 按住中（脉冲停止，物理正常）；dEdge=0 持续且无按键、无 noise lock = ⚠ 信号丢失；第一条数千~数万后跟 `PD noise lock` = 悬空已自动关断（预期）；dS/dL 周期性爆发 = EMI 被拦（无害）；**hb 突然停更** = AppTask 阻塞（复位窗口）或 PD 定时器已停（`factoryreset go` 后）——本身也是诊断信号。dL 常态化 >0 = 毛刺进入测量流（折叠伪测量），指示干扰形态已变（§7.6 残余项）。

**采样分层**（谁产生哪些字段）：
- **中断层** `_pd_gpio_irq_cb`（PB0 双边沿硬件中断）：产生 `dEdge/dS/dL/dM` + 宽度测量（valid_tick）。边沿即触发，毛刺多时中断率可达 ~15 万/s。
- **轮询层** `gPdTimer`（12ms osTimer）→ PostEvent → AppTask 队列 → `PdEventHandler` → `app_btn_mgr_btn_is_pressed()`：每次裸读一次 PB0（N≈86/s，非 1000/12=83，系 RTOS 节拍误差），产生 `hi=n/N`、`win`、存活判定、按下/松手状态机（low_count/high_count）。
- 两层互不阻塞：中断层测宽，轮询层做状态机 + 裸读兜底（§7.7：12ms 点采样对 20ns 毛刺天然不可见——旧轮询版能工作的根本原因）。

**风险监控**：假按下唯一理论通道 = 连续 ≥7 个脉冲被判无效（>140ms 无落窗脉冲）。长期监控方法 = `hb 的 dS/dL 高` 且 `无多余 flag1` = 干扰大但被过滤兜住，无需处理。

### 3.3 `PD release:` 与 `PD timeout:`

```
PD release: low_dur=%lums w=%lums   → 松手确认(flag2 开灯路径)时打印
PD timeout: ev=%lu actual=%lums(nominal 1758) → 1.8s 纠错触发时打印
```

- `release.low_dur`：按下确认→松手的时长（≈真实按键时长 − ~150ms 确认延迟）。**用于积累真实按键时长分布**，是将来评估"松手提交"方案定 T_PRESS_MAX 的数据来源。实测样本：141/199/316/2707ms。
- `release.w`：松手后第一个有效脉冲实测宽度——**真实市电脉宽**（50Hz 应 8~10ms）。
- `timeout.actual` vs 1758ms 标称差值 = AppTask 负载对电容预算的侵蚀量，直接回答"该台设备电容撑不撑得住 1.8s 纠错"。**尚未实测（断电测试未做）**。

**日志链分工**：`hb`（每秒环境体检）→ `press`（事件快照 + 采样健康度）→ `release`（真实按键时长 + 真实脉宽）→ `timeout`（电容余量）。

## 7. 实机运行检讨：dL 之谜与中断层语义（2026-11-18）

背景：v2 固件在干扰台架连续运行，`PD hb` 出现 dEdge≈180~330/s（比 §6 的 19 万/s 温和两个量级）、dS=20~90/s、**dL=4~26/s 持续**。49s 无 flag1/PD press。

### 7.1 dL 的来源：SDK 单通道 flag 折叠伪测量

SDK 分发语义（`sl_gpio.c` `GPIO_EVEN_IRQHandler`，已读源码证实）：

```c
even_flags = get_enabled_pending();   // PB0 只有 1 个 flag 位
clear_interrupts(even_flags);         // 清除先于分发
sl_gpio_dispatch_interrupt(even_flags);
```

- **同通道折叠**：两个物理边沿落在 IRQ 延迟窗（~1µs）内 → flag 只置一次 → 只调用一次回调，升降方向由回调内 `READ_BUTTON()` 读电平**猜**。
- 20ns~300ns 毛刺宽度 ≪ 1µs → **100% 折叠**，且回调执行时毛刺早已结束、读到低电平 → 被当成"下降沿" → `w = now - rise_tick(陈旧)`。
- **w>12ms ≠ 存在超 12ms 高电平**（市电高半周才 8.9ms，物理上不可能）。它的真实语义：**"距上次记录的上升沿已超 12ms 的折叠毛刺"**——伪测量横跨了真的市电下降沿，把低电平时间也算进了"宽度"。
- dS/dL/假 valid 的比例 = 毛刺在半周内位置的分布：低半周早期毛刺 w∈[7,12) 侥幸落窗成假 valid（反而在撑 30ms 保持——该 49s 无 flag1 的原因之一）；中后期 → dL；紧邻 rise → dS。
- dEdge 计的是**调用数**不是物理边沿数（一个毛刺 2 边沿计 1）——所以不能用 `dEdge≈2×(V+S+L)` 反推有效脉冲数。
- NVIC 优先级全程未配置 → 默认 0（最高），GPIO 不被 BLE 抢占，折叠窗已压到自身延迟极限——**配置已最优，无 bug**。

### 7.2 中断层检讨结论

| 检查项 | 结论 |
|---|---|
| ISR 配对/窗口/回绕逻辑 | 无 bug（干净台架实测=离线仿真） |
| SDK 分发 | 折叠语义是结构性限制，测的是"折叠调用流"非物理边沿流 |
| NVIC/回调上下文 | 配置最优 |
| 真信号边沿（间隔 ms 级） | 永不折叠，检测分类测量全正确——**核心功能不受影响** |
| 固件守卫（diff 校验/最短间隔门/mis 计数） | 全部否决：diff 分不清"被剪短的真信号"与"纯随机配对"；间隔门会误杀紧邻毛刺的真边沿；mis 计数给不出可行动信息 |

**rise_tick 消费制（下降沿后清/标志位）的两难**：不清=折叠毛刺拿陈旧时间戳产出伪测量（假 valid/L）；清=垃圾改道，但漂高+dip 型环境里 valid 本来就靠垃圾假刷新撑着，掐掉会塌成恒判按下。这不是对错题，是"哪种垃圾喂 30ms 保持"的选择题——**固件不动，RC 是唯一干净解**（毛刺物理消失后折叠不复存在）。观察 flag1，无人操作出现即立即上 RC。

### 7.3 RC 定量：削顶对检测的影响（回应"电容加大"担忧）

RC 后波形削顶（高半周充不满），GPIO 在 VIH≈0.7·VDD / VIL≈0.3·VDD 翻转。按实测波形（高 8.9ms/低 11.1ms、摆幅 3.3V）稳态计算：

| τ=RC | 充电终值 V₁ | 测得宽度 | 判定 |
|---|---|---|---|
| 0.47ms（4.7k+100nF） | 3.30V 不削 | 8.90ms | 边沿延迟 0.57ms 对称相消，**宽度不变** |
| 2ms | 3.26V | 8.88ms | 无影响 |
| 5ms | 2.80V 明显削顶 | 8.55ms | 仍在窗内 |
| 9ms | 2.33V ≈ VIH | 7.8ms | **16mV 裕量，悬崖边** |
| 10ms | 2.25V < VIH | 无上升沿 | **检测彻底失效** |

规律：**宽度抗削顶**（VIH/VIL 对称分布，上升推迟与下降提前近似相消，τ≤5ms 宽度几乎不动）；**真正的杀手是 V₁ 跌破 VIH** → 整个脉冲消失 → `ac_seen` 永不置位 → 按下永远检不到。悬崖随摆幅缩水前移：摆幅 2.8V 时 τ≈5ms 就死。

**结论：电容不要加大。** 消毛刺需要的是 fc 远离毛刺频段——20ns 毛刺 vs τ=0.47ms（fc≈340Hz）有 5 个数量级衰减分离度，大电容零收益换悬崖。推荐 4.7k+100nF，上限 4.7k+220nF（τ≈1ms），到此为止。

### 7.4 长按 vs 断电的区分（同构问题）

单检测线上"长按住"与"断电"物理同构（都是方波消失），单看这根线永远分不出来。四类方案：

| 方案 | 原理 | 评价 |
|---|---|---|
| 时间窗+行为纠错（**现用**） | <T 算按下翻转，>T 判断电纠错；T=1~3s 由储能电容决定 | 零成本；短断电与按键不可分（§2.2 取舍 1） |
| 脉冲式开关 | 按下发机械窄脉冲，断电持续断开 | 要换开关规格，凌动机械结构不具备 |
| 辅助检测线 | 光耦/辅助绕组直接测母线电压 | 一条线+光耦成本，最干净 |
| **上拉试探**（值得评估） | 力阻差异：按下=开关低阻短接到地，断电=线悬空高阻。信号消失期每 500ms 开内部上拉 ~5ms 读一次：拉高=断电，拉不高=按下 | 零新增器件；破同构、可删 1.8s 超时、消 §2.2 取舍 1 |

上拉试探前提：**断电时 PB0 真悬空高阻**（而非被检测电路偏置成低）。台架验证：①断电测 PB0 对地阻抗；②按住凌动 3s 看 `PD timeout actual`（真实电容余量）。若成立，这是比"松手提交"更彻底的重构方向。

### 7.5 配套规格数据（待确认）

SLISAON 凌动开关规格（来源待核实）：快按 80~300ms、有效脉冲窗口 60~250ms、<40ms 抖动、>300ms 异常拒绝。对照现实现：按下确认实际 150~180ms > 80ms 快按——**80~150ms 快按会被滤掉**。降 `low_count` 阈值（12→5~7）对本批干扰安全（噪声产生不了过滤态 0），但要接住 80ms 快按还得动保持时间/轮询周期——**先让产品确认规格再动**（§4-5 长按规格一起拍）。

### 7.6 实机按压失败根因与纯软件修复（2026-11-23，RC 决策不实施后）

密集干扰台架实机（dEdge 13~16.5 万/s、dS 4.5~8 万/s、dL=0 尖峰型）暴露两个真机特有问题（离线仿真未覆盖——仿真假设每边沿独立可见，真机 IRQ 折叠产生任意宽度）：

1. **折叠伪 valid 导致按压不可检（实锤）**：按压期间（线恒低+满屏毛刺）折叠毛刺被当"下降沿"拿陈旧 rise_tick 随机测宽，落进 [7,12]ms 即成假"有效脉冲" → 30ms 保持永不过期 → 按压全漏。实锤证据：连续按压窗口内 dL 突增 2500~5600/s 且仅 1 次 flag1。
   **修复 = 配对完整性守卫**：ISR 记录上升沿时的边沿计数，下降沿时差≠1（中间夹过其他边沿）→ 判折叠伪测量 → 丢弃计 `mis_cnt`（hb 新增 `dM` 可视），不进窗口。真脉冲高半周干净（diff=1）不受影响；假 valid 通道关闭。
2. **now/valid 读序下溢假锁**：`is_pressed()` 先读 now 后读 valid，两次读之间 ISR 刷新 valid_tick → `now-valid` 下溢（签名：`valid stale 131071999ms` = -1 tick）→ 误判 stale → 假锁 1s。
   **修复 = 读序反转**（valid 先读），保证 valid ≤ now 恒成立。

**决策：RC 不实施，纯软件方案生效**（§6.4 降级为可选硬件备注）。残余代价：① ~15 万中断/s 持续 CPU（实测功能无碍，精测待做）；② 若干扰形态转为"漂高+dip 型"（特征：dL 常态化非零），配对守卫会漏（rise 被折叠刷新），需重新评估。

### 7.7 边沿 flood 台架：点采样存活判定 + 裸读回退（2026-11-23 晚）

16:56 实测（新固件 retry=32015 确认在跑）：开机 212ms 即 `PD noise lock: valid never`，检测全失效。但 **hb `hi≈39/86≈46%` 证明市电方波健在**，`dEdge 1500~2300/s`（锁定态仅在 12ms 复查窗计数）= 折算 15~19 万边沿/s **连续 flood**（两个半周都有毛刺）。测宽层在该环境永远配不上对：真边沿被 ~5µs 间距的毛刺折叠污染，配对守卫把真脉冲和垃圾一起丢弃 → ac_seen 永不置位 → 过宽限即锁。

与 §6.1 台架的区别：那边噪声只在低半周（高半周干净，1659/1659 脉冲全识别）；这边连续淹没——**两种干扰形态，测宽架构只在前者成立**。

**修复 = 存活判定 + 裸读回退**（`app_btn_mgr.cpp`）：

1. `is_pressed()` 每次轮询采一次裸电平，进 64 样本滑动窗（≈0.75s）。窗内高样本 ≥3（`PD_ALIVE_CNT`）= 线上有真实信号，记 `s_pd_alive_seen` 并刷新时刻；粘滞 60s（`PD_ALIVE_HOLD_MS`，按住时高样本稀少，防中途判死）。
2. **alive 时不锁**（stale 判定加 `!alive` 门控）：flood 台架锁了就没得退。
3. **alive 时回退旧轮询语义**：有效脉冲保持期外直接 `return READ_BUTTON()`——与 v0.0.17 完全一致（用户已验证该台架能检测）。按下恒低 12 连 0 → flag1，20ns 毛刺对 12ms 点采样不可见。
4. 干净台架不受影响：有效脉冲每 20ms 刷新，走 hold/过滤态路径，中断滤波照常。**按台架自动切换**。

代价：flood 台架上中断常开，~15-19 万/s 持续（15:51 会话已证明 Matter 可容忍）。

**预期 hb**：有电 `win≈30~40`；按下 `win` 缓降但粘滞保活；悬空 `win=0` → 204ms 锁（原行为不变）。复测清单不变（§4-9）。
