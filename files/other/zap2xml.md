# zap2xml - .zap to PICS XML Converter

Converts Silicon Labs ZAP (`.zap`) configuration files to Matter PICS XML files using the Matter V1.5 PICS XML templates.

## Quick Start

```bash
python zap2xml.py -z window-app.zap -p ".\Matter_V_1_5_PICS_XML_For_RPI" -o output
```

## Command Line Arguments

| Argument | Short | Required | Description |
|----------|-------|----------|-------------|
| `--zap-file` | `-z` | Yes | Path to the `.zap` file to convert |
| `--pics-template` | `-p` | Yes | Path to the folder containing PICS XML templates |
| `--output` | `-o` | Yes | Path to the output folder for generated PICS XML files |

## Usage Examples

### Basic Usage

```bash
python zap2xml.py -z window-app.zap -p ".\Matter_V_1_5_PICS_XML_For_RPI" -o output
```

### Custom Output Directory

```bash
python zap2xml.py -z my-device.zap -p ".\Matter_V_1_5_PICS_XML_For_RPI" -o C:\Projects\my-device\pics
```

## Output Structure

The script generates PICS XML files organized by endpoint (EP0, EP1, etc.):

```
output/
├── EP0/
│   ├── Base.xml
│   ├── Descriptor Cluster Test Plan.xml
│   ├── Basic Information Cluster Test Plan.xml
│   ├── General Commissioning Cluster Test Plan.xml
│   └── ...
├── EP1/

│   ├── Groups Cluster Test Plan.xml
│   ├── Window Covering Cluster Test Plan.xml
│   └── ...
├── EP2/
│   └── ...
└── ...
```

**Note**: EP0 (root endpoint) automatically includes `Base.xml`.

## Features

- ✅ **No duplicate files** - Automatically selects non-duplicate templates (ignores "副本" versions)
- ✅ **Preserves XML headers** - Keeps original template comments (Version, Date, etc.)
- ✅ **Strict true/false** - Sets `support` values strictly based on `.zap` file `included`/`isEnabled` flags
- ✅ **EP naming** - Uses `EP0`, `EP1` format matching reference structure
- ✅ **Base.xml** - Automatically copies Base.xml for root endpoint (EP0)
- ✅ **Server-side only** - Skips client-side clusters
- ✅ **Global attributes skipped** - Excludes FeatureMap (0xFFFC), AttributeList (0xFFFB), etc.

## How It Works

1. **Parse .zap file** - Reads JSON-formatted `.zap` configuration
2. **Extract endpoints** - Maps endpoint types to endpoint IDs
3. **Extract cluster data** - For each cluster, extracts:
   - **Attributes**: PICS codes like `WNCV.S.A0000`, set to `true`/`false` based on `included` flag
   - **Commands**: Accepted (`.CXX.Rsp`) and Generated (`.CXX.Tx`), set based on `isEnabled` flag
   - **Features**: PICS codes like `WNCV.S.F00`, set based on `included` flag
4. **Match templates** - Maps cluster names to PICS XML template files
5. **Generate XML** - Updates template with support values, preserves original header comments

## Prerequisites

- Python 3.6 or higher
- Matter V1.5 PICS XML templates directory (e.g., `.\Matter_V_1_5_PICS_XML_For_RPI`)

## Troubleshooting

### "Could not find matching PICS XML template"
- Verify the template directory contains the correct PICS XML files
- Check cluster name mapping in `CLUSTER_TO_PICS_DICT` in the script
- Add custom mapping if needed

### "No endpoints found in .zap file"
- Verify the .zap file is valid JSON with `endpoints` and `endpointTypes` sections
- Check the file is not corrupted or empty

### Output differs from reference (aok-pics-1.5)
- Different .zap files produce different outputs (each device has unique configuration)
- Verify the .zap file matches the expected device configuration

## Notes

- Only **server-side** clusters are processed (`side="server"`)
- **Disabled** clusters (`enabled=0`) are skipped
- **Client-side** clusters (e.g., OTA Software Update Provider) are skipped
- Global attributes (0xFFFC, 0xFFFB, 0xFFFA, 0xFFF9, 0xFFF8, 0xFFFD) are excluded
- Template files with "副本" suffix are ignored in favor of clean versions

# zap2Xml 工具分析

这是一个将 Silicon Labs ZAP 配置文件转换为 Matter PICS XML 文件的 Python 脚本。

## 工具概述

**zap2Xml** 是一个自动化工具，根据 ZAP 配置文件内容，按照 Matter V1.5 规范生成对应的 PICS（协议实现一致性声明）XML 文件。

## 核心功能

### 1. 集群名称映射
- 处理 ZAP 文件和 PICS XML 模板之间的命名不一致问题
- 特殊处理 Network Commissioning 集群（WiFi/Thread/Ethernet 变体）
- 定义了超过 75 个集群名称映射规则

### 2. 智能 PICS 项判断

| 类型 | 处理规则 |
|------|----------|
| 服务端项 (.S.*) | 根据 ZAP 中集群的服务端配置设置 |
| 客户端项 (.C.*) | 根据 ZAP 中集群的客户端配置设置 |
| 手动项 (.S.M.* / .C.M.*) | 设为 false（ZAP 无法配置此类项）|
| 全局属性 | 始终设为 true（FeatureMap、ClusterRevision 等）|

### 3. 特殊集群处理

- **OTA 软件更新**：将 Provider（服务端）和 Requestor（客户端）合并到单个模板
- **网络配置**：根据 FeatureMap 选择对应的模板（WiFi/Thread/Ethernet）

### 4. Base.xml 动态生成
根据 ZAP 数据自动生成：
- 通信能力（BLE、WiFi、Thread、以太网）
- 设备角色（Commissionee、Commissioner、Controller）

## 工作流程
```c
ZAP 文件 (JSON) → 解析集群 → 匹配模板 → 更新 PICS 项 → 输出 XML  
```
### 主要函数说明

| 函数 | 功能 |
|------|------|
| `extract_clusters_from_zap()` | 从 ZAP 数据中提取集群信息 |
| `map_cluster_name_to_pics_xml()` | 将集群名称映射到对应的 PICS 模板 |
| `determine_server_support()` | 判断服务端 PICS 项的值 |
| `determine_client_support()` | 判断客户端 PICS 项的值 |
| `generate_base_xml()` | 生成 Base.xml 配置文件 |
| `generate_pics_xml_for_ota()` | 特殊处理 OTA 集群 |

## 使用方法

```c
python zap2xml.py -z <zap文件路径> -p <PICS模板目录> -o <输出目录>
```
参数说明：
- -z, --zap-file：输入的 .zap 文件路径
- -p, --pics-template：PICS XML 模板文件夹路径
- -o, --output：生成的 PICS XML 文件输出目录

输出结构
```c
输出目录/
├── EP0/
│   ├── Base.xml
│   ├── On-Off Test Plan.xml
│   └── ...
├── EP1/
│   └── ...
└── ...
```

## 应用场景

1. **Matter 设备认证**：自动生成认证所需的 PICS 文件
2. **ZAP 配置验证**：确保配置与 PICS 声明一致
3. **持续集成**：可作为 CI 流程的一部分自动生成文档

- ✅ 保留 XML 注释和格式
- ✅ 支持多端点（Endpoint）处理
- ✅ 增量更新（只修改变化的项）
- ✅ 详细的日志输出，便于调试
