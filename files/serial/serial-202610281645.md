# Matter 通用串口协议

> 文档版本：V0.01
>
> **适用设备**：灯(OnOff/ Dimmable/ CT/ Extended Color)、窗帘(Window Covering)。  
> 开关(OnOff Switch/ 场景按键开关)、传感器(温湿度/ 光照/ 占空等)。    
>

---

## 1. 设计原则

1. **一帧一事务**：每条指令由序列号(SN)唯一确定，重发不改变 SN
2. **按请求应答**：所有命令帧(查询/控制/上报)一律回**与请求同标识的应答帧**——通用帧同 Config，数据帧同 Endpoint/Cid/Aid
    - 通用帧：成功用LEN=0 确认，查询应答携带数据(LEN≥1)
    - 数据帧：属性应答携带当前值(Len=n)，命令请求或应答/上报 ACK 用 Len=0(无 Value)
    - 失败则不应答，由发送方超时兜底
    - 帧内设 1 字节 **Flag**(SN之后，bit0~bit3，帧类/方向/主动或被动上报/需不需要ACK)
3. **CRC8 校验**：失败帧直接丢弃、不回ACK，由发送方判断是否要超时重发
4. **低功耗优先**：MCU 无事件即可休眠，Matter发包前先唤醒
5. **字节序**：**大端**: 数值高字节在前
6. **多实例**：设备多实例覆盖
7. **扩展性**：Config 与 Cluster 空间分区预留

>大端（Big-Endian, BE）：高字节在前，低字节在后。0x1234 → 内存/线上顺序 12 34。  
```c
buf[0] = (uint16_t)val >> 8;buf[1] = (uint16_t)val & 0xFF;  //Tx, H go first
uint16_t val = ((uint16_t)buf[0] << 8) | buf[1];            //Rx
```
>小端（Little-Endian, LE）：低字节在前，高字节在后。0x1234 → 内存/线上顺序 34 12。  
```c
buf[0] = (uint16_t)val & 0xFF; buf[1] = (uint16_t)val >> 8; //Tx, L go first
uint16_t val = buf[0] | ((uint16_t)buf[1] << 8);            //Rx
```

## 2. 物理层与低功耗接口

### 2.1 UART

| 项目 | 参数 |
| --- | --- |
| 波特率 | 9600 bps |
| 格式 | 8N1，无流控 |
| 电平 | 与Matter VCC 供电电平一致 |
| 帧间隔 | 相邻两帧之间 ≥ 50 ms |

### 2.2 硬件连接

| Matter | 连接方向 | MCU 主控 |
| --- | --- | --- |
| Wakeup(PXx) | → | Wakeup(Interrupt GPIO) |
| Uart Tx(PXx) | → | MCU Rx |
| Uart Rx(PXx) | ← | MCU Tx |

### 2.3 唤醒时序

- **Matter → MCU**：发送数据前，Matter先拉低 Wakeup 引脚保持 **2 ms**，再发送数据帧
- **MCU → Matter**：数据帧前先发送 **3 个 0x00 前导码**，再发送数据帧
- **空闲态**：TX / RX / Wakeup 三线均保持**高电平**

- **SN**：发送方独立计数器，超出 0xFFF0 回绕到 0。
    - 0xFFF1~0xFFFF 为保留值(将来可能作特殊帧扩展)，不作普通事务 SN。
    - 命令帧用发送方自己的计数器；应答帧回显被应答帧的 SN。
- **通用帧 Config**：命令编号(0x01~0x05、0xE0~0xE3，见通用指令表)。
- **数据帧 Len + Value**：Len(1B)=Value 实际字节数(243以内，整帧数据包设计是255以内)
  - Value 承载属性值/命令参数/上报值(编码见数据指令表)
- **CRC8**：对 **SN 起至 PDU 末字节**计算，覆盖 SN、Flag 与全部 PDU 字段
    - 不含帧头 `55 AA` 与 CRC 自身(Flag 决定帧性质，必须纳入校验)
    - 通用帧/数据帧同一算法

### 3.3 CRC8

- **算法**：CRC-8，POLY=`0x07`，INIT/SEED=`0x00`，无输入输出反射，无异或输出

```c
uint8_t crc8(const uint8_t *data, uint16_t len)
{
    uint8_t crc = 0x00;                    /* SEED */
    while (len--) {
        crc ^= *data++;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
    }
    return crc;
}
```

## 4. 应答机制

### 4.1 通用帧应答(Config 应答)

- **命令帧(Flag=0x0C Matter→MCU / 0x0E MCU→Matter)**：接收方**必须回同 Config 应答帧**(Flag=0x02 / 0x00，SN 回显)；无法处理的命令帧(未知 Config/长度错等)**不应答**，由发送方超时兜底。
- **应答帧(Flag=0x02 / 0x00)**：SN 回显被应答命令帧 SN，**不再触发应答**；接收方按 SN 匹配本端挂起事务，无匹配则静默丢弃。

**应答帧 Payload(合一应答，收到即事务完成)**

- **LEN=0**：确认(ACK)——控制与上报类命令的成功应答统一为此形式
- **LEN≥1**：查询类应答携带数据(按通用指令表定义)

### 4.2 数据帧应答(Endpoint/Cid/Aid 应答)

- **控制/查询(Flag=0x0D)**：MCU 执行后回同 Endpoint/Cid/Aid、Flag=**0x03**、SN 回显、合一应答：
    - 属性类(Aid=标准属性)：Len=n，Value=**执行后的当前值**；
    - 命令类(Aid=0xFCxx)：**Len=0，无 Value**，表示命令已执行(状态由对应属性帧另行上报)。
- **命令请求(Flag=0x0D, Aid=0xFCxx)**：**Len=0，无 Value**(命令参数为可选扩展，当前命令均无参数)。
- **上报(Flag=0x0F)**：Matter 回同 Endpoint/Cid/Aid、Flag=**0x01**、SN 回显、**Len=0，无 Value**(ACK)。
- **失败=不应答**：未知 Cid/Aid、Value 越界、设备忙等一律静默不回，由发送方超时兜底(与通用帧一致)。
- CRC 失败静默丢弃；重发耗尽仍失败时，由后续上报/状态同步兜底。

### 4.3 超时与重发(Flag bit3=1 的通用帧与数据帧)

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| T_ACK_TIMEOUT | **500 ms**(9600 bps 下 247 B 单帧线上耗时约 257 ms，故不得低于 300 ms) | 可通过 0x05 配置，范围 200~2000 ms，掉电不保存 |
| N_RETRY | 2(含首发共 3 次) | 超限放弃本帧并向上层报错 |
| 重发内容 | 原 SN、原 Payload，与首发**完全一致** | **SN 不可递加** |

**两类帧应答对照**：

| 维度 | 通用帧 | 数据帧 |
| --- | --- | --- |
| 请求标识 | Config(1B) | Endpoint + Cid + Aid |
| 请求 Flag | 0x0C(Matter→MCU)、0x0E(MCU→Matter) | 0x0D(Matter→MCU)、0x0F(MCU→Matter) |
| 应答 Flag | 0x02(MCU→Matter)、0x00(Matter→MCU) | 0x03(MCU→Matter)、0x01(Matter→MCU) |
| 成功应答内容 | 控制/上报=**LEN=0**；查询=**LEN≥1 数据** | **Len(1B)+Value(n)**：属性当前值；命令应答/上报 ACK=**Len=0** |
| 失败处理 | 不应答，发送方超时兜底 | 同左 |
| CRC 失败 | 静默丢弃 | 同左 |
| 重发 | Flag bit3=1 时同 SN 重发 ≤2 次 | 同左 |
| SN | 应答回显请求 SN；主动上报用己方计数器 | 同左 |

## 5. SN(序列号)与重发规则

1. **独立计数**：Matter维护 `MATTER_TX_SN`，MCU 维护 `MCU_TX_SN`；
    - 各自从 `0x0000` 递增，互不跟随、不共用空间。
2. **重发不加 SN**：首次发送 SN=N，超时重发仍为 N；仅发送**全新事务**时计数器 +1。
3. **回显应答**：应答帧(Flag bit2=0)SN = 被应答命令帧 SN；
    - 发送方收到"应答帧且 SN 与挂起事务一致"即认为发送成功，停止重发。
4. **主动上报的 SN**：上报方(Matter或 MCU)使用**自己的计数器**取下一个 SN，**不跟随对方 SN**；
    - 接收方据此区分"独立上报"与"对某指令的带数据应答"。
5. **去重**：接收方维护**最近 8 个已处理 SN** 的环形缓存(仅对命令帧 Flag bit2=1)：
   - 收到的命令帧 SN 已在缓存中(重复帧)→ 只重回应答/ACK，丢弃业务数据，不重复执行；
   - 不在缓存 → 正常执行并加入缓存。
6. **回绕安全**：SN 到 `0xFFF0` 后回绕到 `0x0000`；
    - 新帧判据=**不在最近已处理 SN 集合**(命中=重复帧，未命中=新帧)，无其他比较
    - 计数周期为 0xFFF1(0xFFF1~0xFFFF 保留)
7. **上报同样等应答**：任一方向的重要上报同样等对端的应答帧(通用帧同 Config、数据帧同 Endpoint/Cid/Aid)，超时同 SN 重发 ≤ 2 次。
8. **冲突处理(全双工交叉)**：一方正在等应答时收到对方新请求 → **先立即应答对方**(请求标识一致、SN=对方请求 SN)；
    - 继续等自己的应答；
    - 收到"请求标识一致但 SN 不同"的帧按新请求处理。

## 8. 命令集

### 8.1 通用指令表

> **记法**：`B`=字节；`[n]`/`[n-m]`=Payload 内字节下标  
> **Flag 怎么读**(帧头 `55 AA` + SN(2B) 之后的 1 字节，按下表直接对照)
>
> | Flag | 位 3210 | 方向 | 帧性质 | ToDo |
> | --- | --- | --- | --- | --- |
> | **0x0C** | 1100 | Matter→MCU | 命令/查询 | MCU 回**同 Config 应答帧**(0x02) |
> | **0x0E** | 1110 | MCU→Matter | 命令/上报 | Matter 回**同 Config 应答帧**(0x00) |
> | **0x02** | 0010 | MCU→Matter | 应答(被动) | 无需再应答；SN 回显命令帧 |
> | **0x00** | 0000 | Matter→MCU | 应答/确认(被动) | 无需再应答；SN 回显 |
>
> 表中 `Y(0x0C)` 的 **Y**=命令帧(需应答)，括号内=帧内实际字节；`N(0x02)` 的 **N**=应答帧(不再应答)。  
> 例：`55 AA 00 01 0C 01 00 F9` → 0x0C = Matter 查询 MCU；MCU 回 `55 AA 00 01 02 01 00 D5`（0x02 = 应答，SN=0x0001 回显）。  
> **Config**=通用帧 PDU 首字节(命令编号)。**成功应答=LEN=0**；查询应答携带数据。无法处理的命令帧不应答，由发送方超时兜底。

### 8.2 数据指令表

> **帧结构**：`55 AA | SN(2B) | Flag | Endpoint | ClusterID(2B) | AttributeID(2B) | Len(1B) | Value(n) | CRC8`  
> **Endpoint**=实例号(0x01 起，对齐 Matter Endpoint)；**0x00=根节点**(整机级属性，如电量)。  
> **Cid/Aid**=Matter 标准 Cluster/Attribute ID；  
> **Len**=Value 实际字节数(0~243，**0 表示无 Value**，用于命令与 ACK)；**Value** 变长。  
> **Value 按 Matter 属性自然宽度编码**：boolean / enum8 / uint8(0~255)=1B；int16 / uint16=2B；其余按属性定义。  
> 单帧 Value 上限 243B(整帧 ≤255B)；更长的 Matter 属性(字符串/数组等)需上层分片，本版未定义。     
> **Flag 怎么读**(同一位置，数据帧专用 4 个值)：
>
> | Flag | 位 3210 | 方向 | 帧性质 | ToDo |
> | --- | --- | --- | --- | --- |
> | **0x0D** | 1101 | Matter→MCU | 控制/查询 | MCU 回**同 Endpoint/Cid/Aid 的 0x03**：属性类带当前值，命令类 Len=0 |
> | **0x03** | 0011 | MCU→Matter | 回值/确认应答(被动) | 无需再应答；属性带当前值，命令类 Len=0 |
> | **0x0F** | 1111 | MCU→Matter | 主动上报 | Matter 回 **ACK**(0x01，Len=0) |
> | **0x01** | 0001 | Matter→MCU | ACK(被动) | 无需再应答；SN 回显上报帧，Len=0 |
>
> 记法：**bit0=1 都是数据帧；bit1 看方向；bit2=1 是发起方(命令/上报)，bit2=0 是应答方；bit3=1 表示要对方应答。**  
> 例：`55 AA 00 05 0D 01 01 02 00 08 02 00 32 F2` → 0x0D = Matter 下发控制   
> MCU: `55 AA 00 05 03 01 01 02 00 08 02 00 32 22` → 0x03 = 回值应答，SN=0x0005 回显   
> **控制/查询→MCU 回同 Endpoint/Cid/Aid 的当前值(被动回值，合一应答)**；上报→对端回同 Cid/Aid 的 ACK(Len=0，无 Value)。

### 8.3 补充说明

- **上电交互约定**：Matter 上电后以 0x01 查询 MCU 产品信息(确认 MCU 串口就绪并获取 pid/版本)；
    - MCU 上电后主动完整上报一次所有支持属性(状态同步原则)，Matter 对上报的应答即为链路确认；
    - Matter 上电/网络状态变化后主动 0x02 上报。0x05 配置掉电不保存，恢复默认。
- **亮度语义**：Value 0x0000~0x1388(0~5000)为自定义缩放，Matter currentLevel(0~254)由 Matter 换算；
    - 渐变到达目标值后 MCU 应以 Cid=0x0008 数据帧上报最终值。
- **颜色语义**：XY ↔ HS 转换由 **Matter** 完成(控制端可能下发任一格式，MCU 只需实现其一即可)。
- **状态同步原则**：任何控制成功执行后，MCU 必须以对应 Cid/Aid 的数据帧(Flag=0x0F)主动上报当前值；
    - **MCU 上电后应完整上报一次所有支持的属性**
    - Matter 重启后应逐项查询(对应状态查询方向)。应答帧回显请求 SN
    - 主动上报帧用 MCU 自己的计数器。
    - OnOff 的 Toggle 由 MCU 翻转，翻转后必须以 Cid=0x0006 数据帧上报最终状态。
- **多实例(Endpoint)**：数据帧的 Endpoint 字节即实例号(0x01 起=第 1 实例，对齐 Matter Endpoint 编号)；
    - **Endpoint=0=根节点**，用于整机级属性(电量 0x002F/0x000C 等)；
    - 单实例产品固定填 0x01；通用帧(系统/网络/OTA)为整机级，无 Endpoint 概念；
- **帧判别**：Flag bit0 区分通用帧/数据帧，bit1 方向，bit2 主动/应答，bit3 ACK 请求；通用帧再按 Config 分类，数据帧按 Cid/Aid 分类。

**OTA 流程**(Matter 从 Matter OTA Provider 下载自身镜像后，向 MCU 转发 MCU 固件)：

```c
Matter                                          MCU
 |--- 0xE1 New firmware info (pid/ver/size/sum) -->|  (Matter启动时通过0x01 取得 MCU 当前版本)
 |<-- 0xE1 Confirmation (LEN=0) -------------------|  (MCU 擦除 Flash 后应答)
 |<-- 0xE2 [Len=240] ------------------------------|  (MCU 循环拉取，只需给长度)
 |--- 0xE2 [240B firmware data] ------------------>|
 |             ...                                 |
 |<-- 0xE3 0x00/0x01 Upgrade result ---------------|
 |--- 0xE3 Response (FLAG=0, LEN=0) ---------------|  
```

> OTA 期间约定，暂停传感器周期上报  
> MCU 收满 size 字节后按累加和(metadata 头+固件)与大小整包校验，再切镜像、上电报 0xE3  
> 模组自发出 0xE1 起等待 MCU 完成，超时 **150 s** 视为失败  
> 模组内部维护读取偏移，首次读取自动跳过 **10B metadata 头**(magic 2B + size 2B + checksum 1B + version 5B)  
> 升级结果帧 SN 用 MCU 计数器正常递增  
> **固件数据(0xE2 Payload)按字节透传**：其内部字节序由 MCU 架构/编译器决定
