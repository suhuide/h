# Matter 通用串口协议

> 文档版本：V0.01
>
> **适用设备**：灯(OnOff/ Dimmable/ CT/ Extended Color)、窗帘(Window Covering)。  
> 开关(OnOff Switch/ 场景按键开关)、传感器(温湿度/ 光照/ 占空/ 门窗磁/ 水浸等)。    
>
> **术语**：`Ma2M` = Matter发给 MCU(控制/查询/应答)；`M2Ma` = MCU 发给Matter(上报/应答)。

---

## 1. 设计原则

1. **一帧一事务**：每条指令由序列号(SN)唯一确定，重发不改变 SN。
2. **同 CMD 应答**：所有命令帧(查询/控制/上报)一律以**相同命令字**的应答帧应答；
    - 成功=LEN=0 确认(无 Payload)；仅查询应答携带数据(LEN≥1)。失败=不应答，由发送方超时兜底。
    - 帧内设 1 字节**应答标志**(用帧头后第 1 字节bit0,其余bit备用)显式区分**命令帧**与**应答帧**。
3. **CRC8 校验**：失败帧直接丢弃、不回ACK，由发送方判断是否要超时重发。
4. **低功耗优先**：MCU 无事件即可休眠，Matter发包前先唤醒。
5. **字节序**：**大端**，全帧统一。
    - SN 高字节在前；Payload 内多字节数值高字节在前。
    - FLAG/CMD/LEN/CRC8 均为单字节，无字节序问题。
6. **多实例**：设备多实例覆盖。
7. **扩展性**：CMD 空间分区预留。

>大端（Big-Endian, BE）：高字节在前，低字节在后。0x1234 → 内存/线上顺序 12 34。  
```c
buf[0] = (uint16_t)val >> 8;buf[1] = (uint16_t)val & 0xFF;  //Tx, H go first
uint16_t val = ((uint16_t)buf[0] << 8) | buf[1];            //Rx
```
>小端（Little-Endian, LE）：低字节在前，高字节在后。0x1234 → 内存/线上顺序 34 12。  
```c
buf[0] = (uint16_t)val & 0xFF; buf[1] = (uint16_t)val >> 8; //Tx, L go first
uint16_t val = buf[0] | ((uint16_t)buf[1] << 8);            //Rx
```

## 2. 物理层与低功耗接口

### 2.1 UART

| 项目 | 参数 |
| --- | --- |
| 波特率 | 9600 bps |
| 格式 | 8N1，无流控 |
| 电平 | 与Matter VCC 供电电平一致 |
| 帧间隔 | 相邻两帧之间 ≥ 50 ms |
| 字节序 | 大端 |

### 2.2 硬件连接

| Matter | 连接方向 | MCU 主控 |
| --- | --- | --- |
| Wakeup(PXx) | → | Wakeup(Interrupt GPIO) |
| Uart Tx(PXx) | → | MCU Rx |
| Uart Rx(PXx) | ← | MCU Tx |

### 2.3 唤醒时序

- **Matter → MCU**：发送数据前，Matter先拉低 Wakeup 引脚保持 **2 ms**，再发送数据帧。
- **MCU → Matter**：数据帧前先发送 **3 个 0x00 前导码**，再发送数据帧(供Matter从低功耗状态恢复)。
- **空闲态**：TX / RX / Wakeup 三线均保持**高电平**。
- **休眠模型**：MCU 可随时休眠；Matter发数据需先唤醒 MCU。Matter自身休眠/侦听策略由Matter内部管理。

## 3. 帧格式

Matter 与 MCU 的通讯数据采用大端格式，帧格式如下。

| 帧头 | 应答标志 | SN(序列号) | CMD(命令字) | LEN(数据长度) | Payload(有效数据) | CRC8(校验) |
| --- | --- | --- | --- | --- | --- | --- |
| 2 byte | 1 byte | 2 byte | 1 byte | 1 byte | N byte | 1 byte |
| 0x55 0xAA | bit0：1=命令帧 / 0=应答帧 | 0x0000 ~ 0xFFF0 | CMD | 0 ~ 247 | 参数或数据 | CRC8 |

- **应答标志(FLAG)** bit0有效， bit1~7 保留(发送为 0，接收忽略)
    - bit0=1 为**命令帧**(请求/主动上报，需要应答)；
    - bit0=0 为**应答帧**(与触发它的命令帧同 CMD，不再触发应答)。
- **SN**：发送方独立计数器，超出 0xFFF0 回绕到 0。
    - 0xFFF1~0xFFFF 为保留值(将来可能作特殊帧扩展)，不作普通事务 SN。
    - 命令帧用发送方自己的计数器；应答帧回显被应答帧的 SN。
- **LEN**：Payload 有效字节数。
- **CRC8**：对**应答标志(FLAG)起至 Payload 末字节**计算
    - 覆盖 FLAG、SN、CMD 及载荷；不含帧头 `55 AA` 与 CRC 自身(FLAG 决定帧性质，必须纳入校验)。

### 3.1 CRC8

- **算法**：CRC-8，POLY=`0x07`，INIT/SEED=`0x00`，无输入输出反射，无异或输出。
- **计算范围**：**应答标志字段起至 Payload 最后一字节**(不含帧头、CRC 本身；
    - FLAG 决定帧性质，必须纳入校验)。

```c
uint8_t crc8(const uint8_t *data, uint16_t len)
{
    uint8_t crc = 0x00;                    /* SEED */
    while (len--) {
        crc ^= *data++;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
    }
    return crc;
}
/* data = 帧内从应答标志起(偏移 2)到 Payload 末字节；调用示例：
   crc8(&frame[2], 2 + LEN);   frame[0..1] = 55 AA */
```

> **CRC 失败处理**：接收方**静默丢弃**，不回 ACK/NACK；发送方超时后按需以**同一 SN** 重发。

### 3.2 帧接收状态机要点

1. 同步搜索 `55 AA` → 按 LEN 收满 Payload → 校验 CRC8 → 按应答标志分类。
2. LEN 上限 247，超限或帧间隔超时(建议 ≥ 100 ms 无后续字节判定帧尾失败)即丢弃重同步。
3. 前导码 `00 00 00` 由接收方在帧同步搜索中自然跳过，无需特殊处理。

## 4. 应答机制

### 4.1 应答方式

**按应答标志分类，显式规则，消除"这是应答还是新指令"的歧义**
- **命令帧(FLAG bit0=1)**：所有请求与主动上报。接收方**必须回同 CMD 应答帧**。
- **应答帧(FLAG bit0=0)**：与触发它的命令帧**同 CMD**，SN 回显该命令帧 SN，**无需触发应答**。
    - 接收方按 SN 匹配本端挂起事务；无匹配(应答丢失后的迟到帧等)则静默丢弃。

**应答帧 Payload(合一应答，收到应答帧即传输确认/事务完成)**

- **LEN=0**：确认(ACK)——控制与上报类命令的成功应答统一为此形式
- **LEN≥1**：查询类应答携带数据(按总表定义)

### 4.2 超时与重发参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| T_ACK_TIMEOUT | **500 ms**(9600 bps 下 247 B 单帧线上耗时约 257 ms，故不得低于 300 ms) | 可通过 0x05 配置，范围 200~2000 ms，掉电不保存 |
| N_RETRY | 2(含首发共 3 次) | 超限放弃本帧并向上层报错 |
| 重发内容 | 原 SN、原 Payload，与首发**完全一致** | **SN 不可递加** |

## 5. SN(序列号)与重发规则

1. **独立计数**：Matter维护 `MATTER_TX_SN`，MCU 维护 `MCU_TX_SN`；
    - 各自从 `0x0000` 递增，互不跟随、不共用空间。
2. **重发不加 SN**：首次发送 SN=N，超时重发仍为 N；仅发送**全新事务**时计数器 +1。
3. **回显应答**：应答帧(FLAG bit0=0)SN = 被应答命令帧 SN；
    - 发送方收到"应答帧且 SN 与挂起事务一致"即认为发送成功，停止重发。
4. **主动上报的 SN**：上报方(Matter或 MCU)使用**自己的计数器**取下一个 SN，**不跟随对方 SN**；
    - 接收方据此区分"独立上报"与"对某指令的带数据应答"。
5. **去重**：接收方维护**最近 8 个已处理 SN** 的环形缓存(仅对命令帧 FLAG bit0=1)：
   - 收到的命令帧 SN 已在缓存中(重复帧)→ 只重回应答/ACK，丢弃业务数据，不重复执行；
   - 不在缓存 → 正常执行并加入缓存。
6. **回绕安全**：SN 到 `0xFFF0` 后回绕到 `0x0000`；
    - 新帧判据=**不在最近已处理 SN 集合**(命中=重复帧，未命中=新帧)，无其他比较
    - 计数周期为 0xFFF1(0xFFF1~0xFFFF 保留)
7. **上报同样等应答**：任一方向的重要上报同样等对端的同 CMD 应答帧，超时同 SN 重发 ≤ 2 次。
8. **冲突处理(全双工交叉)**：一方正在等应答时收到对方新请求 → **先立即应答对方**(CMD 一致、SN=对方请求 SN)；
    - 继续等自己的应答；
    - 收到"CMD 一致但 SN 不同"的帧按新请求处理。

## 6. 交互流程

### 6.1 正常流程(控制类，同 CMD 应答)

```c
Matter                                          MCU
 |---- CMD=0x10, FLAG=1, SN=N, Payload=On ---->|
 |<--- CMD=0x10, FLAG=0, SN=N, LEN=0 ---------|    (应答帧，SN 回显，LEN=0 确认，无 Payload)
```

### 6.2 超时重发

```c
Matter                                          MCU
 |---- CMD=0x10, FLAG=1, SN=N ------------X  (帧丢失/CRC错被丢弃)
 |        T_ACK_TIMEOUT(500ms) 超时
 |---- CMD=0x10, FLAG=1, SN=N (原帧重发) -->|
 |<--- CMD=0x10, FLAG=0, SN=N -------------|
```

### 6.3 主动上报(同 CMD LEN=0 确认)

```c
MCU                                           Matter
 |---- CMD=0x50, FLAG=1, SN=MCU_TX_SN++ -->|
 |<--- CMD=0x50, FLAG=0, SN=回显, LEN=0 ---|    (ACK，同 CMD 确认)
```

### 6.4 双方同时发送

```c
Matter                                          MCU
 |---- CMD=0x10, FLAG=1, SN=N ------------>|
 |<---- CMD=0x40, FLAG=1, SN=M -----------|     (MCU 同时上报按键事件)
 |<---- CMD=0x10, FLAG=0, SN=N -----------|     (MCU 先立即应答 Matter 请求)
 |---- CMD=0x40, FLAG=0, SN=M, LEN=0 ----->|     (Matter 确认 MCU 上报，同 CMD 确认)
 |<---- CMD=0x10, FLAG=0, SN=N ------------|     (Matter 继续等自己的应答，超时则重发)
```

## 8. 命令集

### 8.1 总表

> **记法**：`B`=字节；`[n]`/`[n-m]`=Payload 内字节下标(从 0 起，多字节为大端)；`指令细则`为该行帧的完整示例(CRC 为真实计算值)。  
> **FLAG(应答标志)列**=帧内 bit0：**Y(=1) 命令帧**(发起请求/上报，需要应答)；**N(=0) 应答帧**。方向=本行帧的发送方向。  
> **实例号(Index)**：灯/窗帘/开关/传感器类命令 Payload **首字节=实例号**(0x01 起=第 1 实例)；  
> 单实例产品固定填 0x01、可不处理其值，**但字节位置必须保留**。网络/电池/OTA 类命令无实例号。  
> **应答帧规则(全表统一)**：与触发它的命令帧**同 CMD**、FLAG=N(0)、**SN 回显该命令帧的 SN**；  
> **成功=LEN=0 确认(无 Payload、无状态字节)**；查询类应答携带数据(LEN≥1，首字节=实例号)；  
> 无法处理的命令帧(未知 CMD/长度错/参数越界/忙等)**不应答**，由发送方超时重发兜底。  
> 每行成对可对账：N 行的 SN 与其 Y 行相同。

### 8.2 补充说明

- **上电交互约定**：Matter 上电后以 0x01 查询 MCU 产品信息(确认 MCU 串口就绪并获取 pid/版本)；
    - MCU 上电后主动完整上报一次所有支持属性(状态同步原则)，Matter 对上报的应答即为链路确认；
    - Matter 上电/网络状态变化后主动 0x02 上报。0x05 配置掉电不保存，恢复默认。
- **亮度语义**：亮度 0~100% 与 Matter currentLevel(0~254)由 Matter 线性换算；
    - 渐变到达目标值后 MCU 应以 0x12 上报最终值。
- **颜色语义**：XY ↔ HS 转换由 **Matter** 完成(控制端可能下发任一格式，MCU 只需实现其一；
    - 两类都实现的产品按 0x23 模式路由)。
- **状态同步原则**：任何控制成功执行后，MCU 必须以对应"状态上报"CMD 主动上报当前值；
    - **MCU 上电后应完整上报一次所有支持的属性**
    - Matter 重启后应逐项查询(对应状态查询方向)。应答帧回显请求 SN
    - 主动上报帧用 MCU 自己的计数器。
    - OnOff 的 Toggle 由 MCU 翻转，翻转后必须以 0x10 上报最终状态。
- **多实例**：灯/窗帘/开关/传感器类命令 Payload **首字节=实例号**(0x01 起=第 1 实例)；
    - 实例号 1 起：对齐 Matter Endpoint 编号(Endpoint 0 为根节点专用)与既有协议索引习惯；0x00 预留不用，禁用位掩码索引(1/2/4)；
    - 单实例产品固定填 0x01、可不处理其值，**但字节位置必须保留**(解析时跳过、发送时填 0x01)；
    - 网络管理/电池/OTA 类命令(0x01~0x08、0xE0~0xE3)为整机级，无实例号；
    - 0x40 按键的"键号"即实例索引，不再另加。
- **同 CMD 多角色判别(0x10/0x12/0x20/0x50 系列通用)**：接收方按"方向 → FLAG → LEN → SN 匹配"逐级分类，零歧义；
    - Matter→MCU：FLAG=1 且 LEN=1=状态查询(Payload=实例号)；FLAG=1 且 LEN≥2=控制命令(首字节=实例号)；FLAG=0=对 MCU 上报的确认；
    - MCU→Matter：FLAG=1=主动上报(首字节=实例号)；FLAG=0 且 LEN=0=控制/上报确认；FLAG=0 且 LEN≥1=查询应答(SN 匹配挂起事务，首字节=实例号)。
- **窗帘电机**：运动中**每变化 5% 或状态切换(Idle↔Opening/Closing)必须上报 0x34**；
    - 低电量 Critical 时拒绝运动指令(不应答，静默拒绝)。
- **电池供电按键开关**：按键唤醒 MCU → 0x40 上报 → 等同 CMD 应答(LEN=0) → 回休眠；
    - 应答超时同 SN 重发(事件不丢)。
- **TLV 格式定义(0x56 批量上报；0x55 类型枚举共用)**：
    - 帧 Payload = 若干 TLV **紧密串联**，无对齐填充、无结束符，TLV 个数由 LEN 收尾判定；
    - 每个 TLV：`Type(1B) + Len(1B) + Value(Len B)`，Len 仅指 Value 字节数；
    - **Value = 实例号(1B，0x01 起) + 编码值(按下表)**，多字节编码值为大端，与单类型上报指令的编码一致(仅多出实例号)；
    - 同帧同 Type 至多出现一次，重复时取第一个、忽略后续；
    - LEN≥4(至少携带 1 个 TLV)。

    | Type | 传感器 | Value 编码(实例号后) | 缩放/单位 |
    | --- | --- | --- | --- |
    | 0x00 | 温度 | int16 大端 | ×0.01 ℃ |
    | 0x01 | 湿度 | uint16 大端 | ×0.01 %RH |
    | 0x02 | 光照 | uint16 大端 | lux |
    | 0x03 | 占空 | uint8 | 0 无人 / 1 占用 |
    | 0x04 | 门窗磁 | uint8 | 0 关闭 / 1 打开 |
    | 0x05~0xFF | 保留 | 新类型(CO2/PM2.5/水浸/烟雾等)在此扩展，不新增 CMD | — |

    - 0x55 的变化阈值 `[5-6]` 按同表缩放(如温度 0.5℃ → 50)。
- **节流策略(低功耗关键)**：
  - **阈值上报**：变化超过 0x55 配置阈值才上报(默认建议：温度 ≥0.5 ℃、湿度 ≥3 %RH、光照 ≥10 %)；
  - **兜底上报**：即使无变化，每个最大上报间隔必须上报一次(证明在线、防状态漂移)；
  - **批量合并**：多传感器同周期到期时合并进一帧 0x56，减少唤醒次数；
  - 新增传感器类型(CO2、PM2.5、水浸、烟雾等)优先扩展上表 Type 枚举，不新增 CMD。

**OTA 流程**(Matter 从 Matter OTA Provider 下载自身镜像后，向 MCU 转发 MCU 固件)：

```c
Matter                                          MCU
 |---- 0xE0 查询当前版本 ------------------->|
 |<--- 0xE0 {"p","v"} ----------------------|    (与 0xE1 版本比对，相同则结束)
 |---- 0xE1 新固件信息(pid/ver/size/sum) --->|
 |<--- 0xE1 0x00 接受 ----------------------|    (MCU 擦除 Flash 后应答)
 |<--- 0xE2 [Offset=0, Len=240] ------------|    (MCU 循环拉取)
 |---- 0xE2 [Offset, 数据] ---------------->|
 |              ...                         |
 |<--- 0xE3 0x00/0x01 升级结果 --------------|
 |---- 0xE3 应答(FLAG=0, LEN=0) ------------|
```

> OTA 期间约定，暂停传感器周期上报  
> MCU 收满 size 字节后按累加和与大小整包校验，再切镜像、上电报 0xE3  
> 升级结果帧 SN 用 MCU 计数器正常递增  
> **固件数据(0xE2 Payload)按字节透传**：其内部字节序由 MCU 架构/编译器决定(如 Cortex-M 为小端)，  
> 协议不转换、两端不得做字节序变换；帧内 Offset/Length/pid/大小等协议字段仍为大端。

## 9. 低功耗设计

1. **引脚空闲高电平**；Matter发包前拉低 Wakeup 2 ms，MCU 发包前 3 × 0x00 前导码。
2. **事件驱动，无周期心跳**：双方均不做周期性轮询；
    - 在线检测用 0x01 / 0x03 查询，传感器保底用最大上报间隔(0x55)。
3. **上报合并**：多传感器同周期数据用 0x56 批量帧一次携带。
4. **MCU 自由休眠**：MCU自主决定是否要休眠；Matterr控制/查询前先唤醒。
5. **参数缺省**：T_ACK_TIMEOUT=500 ms、N_RETRY=2(共 3 次)。
6. **电量联动**(Option)
    - 电量 ≤ Warning(0x08=1)→ 上报间隔加倍、禁用 0x24 连续调光；
    - 电量 ≤ Critical(0x08=2)→ 拒绝电机/射频重操作(窗帘运动指令不应答，静默拒绝)，仅保留本地按键与低电上报。
