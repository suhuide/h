# serial.md — Matter 通用串口协议（模组 ↔ MCU）

> 文档版本：V1.00
>
> **定位**：本协议以 **s.md（Matter 与控制器通讯协议）** 为主体框架，**s2.md（BLE APP 通讯接口协议）** 补充 ACK/NACK 应答机制，**readme.md（串口通信 SN 号与重发机制设计要点）** 规范 SN 与重发行为，并整合通用化重构。
>
> **适用设备**：灯（OnOff / Dimmer / 色温 CT / 扩展颜色 Extended Color）、窗帘（Window Covering）、开关（OnOff Switch / 场景按键开关）、传感器（温湿度 / 光照 / 占空 / 门窗磁 / 水浸等）以及电池类低功耗设备。
>
> **术语**：`Ma2M` = 模组发给 MCU（多为控制/查询下行）；`M2Ma` = MCU 发给模组（多为应答/上报上行）。

---

## 1. 总体设计原则

1. **一帧一事务**：每条指令由序列号（SN）唯一确定，重发不改变 SN。
2. **同 CMD 应答**：查询/控制指令以**相同命令字**应答（沿用 s.md）；主动上报以 **CMD 0x00 通用确认帧**应答。帧格式不设应答标志字段。
3. **CRC8 校验**：失败帧直接丢弃、不回任何响应，由发送方超时重发（readme.md 建议 6）。
4. **低功耗优先**：MCU 无事件即休眠，模组发包前先唤醒；上报支持"阈值 + 批量 + 兜底"节流。
5. **字节序**：**大端**（沿用 s.md；Payload 内多字节数值均为大端）。
6. **扩展性**：CMD 空间分区预留；新增传感器类型优先扩展枚举/TLV，不新增 CMD。

## 2. 物理层与低功耗接口

### 2.1 UART

| 项目 | 参数 |
| --- | --- |
| 波特率 | 9600 bps（本版仅 9600；更高波特率协商留作后续版本预留扩展） |
| 格式 | 8N1，无流控 |
| 电平 | 与模组 VCC 供电电平一致 |
| 帧间隔 | 相邻两帧之间 ≥ 50 ms |
| 字节序 | 大端 |

### 2.2 连接（含唤醒线）

| Matter 模组 | 连接方向 | MCU 主控 |
| --- | --- | --- |
| Wakeup(PA5) | → | Wakeup(GPIO) |
| Uart Tx(PB2) | → | Rx |
| Uart Rx(PB1) | ← | Tx |

### 2.3 唤醒时序（低功耗核心）

- **模组 → MCU**：发送数据前，模组先拉低 Wakeup 引脚保持 **2 ms**，再发送数据帧。
- **MCU → 模组**：数据帧前先发送 **3 个 0x00 前导码**，再发送数据帧（供模组从低功耗状态恢复）。
- **空闲态**：TX / RX / Wakeup 三线均保持**高电平**。
- **休眠模型**：MCU 无事件可随时休眠（无需向模组申请许可）；模组有下行时按上述时序唤醒 MCU。模组自身休眠/侦听策略由模组内部管理，对 MCU 透明。

## 3. 帧格式

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 帧头 | 2 byte | 固定 `0x55 0xAA` |
| 版本 | 1 byte | 当前 `0x01` |
| SN（序列号） | 2 byte | 发送方独立计数器，`0x0000 ~ 0xFFF0`，超出回绕到 0（见 §5） |
| CMD（命令字） | 1 byte | 见 §7 命令空间划分 |
| LEN（数据长度） | 1 byte | Payload 字节数，`0 ~ 247` |
| Payload | N byte | 参数或数据 |
| CRC8 | 1 byte | 见 §3.1 |

### 3.1 CRC8

- **算法**：CRC-8，POLY=`0x07`，INIT/SEED=`0x00`，无输入输出反射，无异或输出（与 s2.md 包头校验同标准）。
- **计算范围**：**SN 字段起至 Payload 最后一字节**（不含帧头、版本、CRC 本身；readme.md 建议 6：CRC 覆盖 SN 及载荷）。

```c
uint8_t crc8(const uint8_t *data, uint16_t len)
{
    uint8_t crc = 0x00;                    /* SEED */
    while (len--) {
        crc ^= *data++;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
    }
    return crc;
}
/* data = 帧内从 SN 起到 Payload 末字节；调用示例：
   crc8(&frame[3], 3 + LEN);   frame[0..2] = 55 AA VER */
```

> **CRC 失败处理**：接收方**静默丢弃**，不回 ACK、不回 NACK，也不用其 SN 回应任何帧；发送方超时后以**同一 SN** 重发。

### 3.2 帧接收状态机要点

1. 同步搜索 `55 AA` → 校验版本 → 按 LEN 收满 Payload → 校验 CRC8。
2. LEN 上限 247，超限或帧间隔超时（建议 ≥ 100 ms 无后续字节判定帧尾失败）即丢弃重同步。
3. 前导码 `00 00 00` 由接收方在帧同步搜索中自然跳过，无需特殊处理。

## 4. 应答机制

### 4.1 应答方式（按 CMD 定义，二选一）

| 方式 | 说明 |
| --- | --- |
| **同 CMD 应答**（查询/控制类默认，沿用 s.md） | 应答帧 CMD 与请求帧相同，**SN 回显请求帧 SN**，Retry 帧同样回显；Payload 携带结果数据或状态值 |
| **通用确认帧（CMD 0x00）** | 用于**主动上报类**指令（状态/传感器/按键/电池/错误码上报）；SN 回显被确认帧 SN |

### 4.2 CMD 0x00 通用确认帧 Payload（1 字节状态码）

| 码 | 含义 |
| --- | --- |
| 0x00 | ACK（成功，含识别为重复帧后重回的 ACK） |
| 0x01 | Busy（忙，请稍后重试） |
| 0x02 | 未知 CMD |
| 0x03 | 长度/格式错误 |
| 0x04 | 参数越界（如百分比 > 100） |
| 0x05 | 设备忙于 OTA / 配网，拒绝执行 |

> 状态码分类对齐 s2.md 的 NACK 语义（busy / unknown cmd / len error），统一并入 0x00 帧的 payload 表达。CRC 错误不产生 NACK（静默丢弃，见 §3.1）。

### 4.3 超时与重试参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| T_ACK_TIMEOUT | **500 ms**（9600 bps 下 247 B 单帧线上耗时约 257 ms，故不得低于 300 ms） | 可通过 0x05 配置，范围 200~2000 ms，掉电不保存；OTA 期间建议放宽至 1000 ms |
| N_RETRY | 2（含首发共 3 次） | 超限放弃本帧并向上层报错（MCU 侧可经 0x0F 上报通信失败） |
| 重发内容 | 原 SN、原 Payload，与首发**完全一致** | **SN 严禁递加**（readme.md §1） |

## 5. SN（序列号）与重发规则（readme.md 全量落档）

1. **独立计数**：模组维护 `MA_TX_SN`，MCU 维护 `MCU_TX_SN`，各自从 `0x0000` 递增，互不跟随、不共用空间。
2. **重发不加 SN**：首次发送 SN=N，超时重发仍为 N；仅发送**全新事务**时计数器 +1。
3. **回显应答**：应答/确认帧 SN = 被确认帧 SN。发送方收到"CMD 一致且 SN 一致"的帧即认为发送成功，停止重发。
4. **主动上报的 SN**：上报方（模组或 MCU）使用**自己的计数器**取下一个 SN，**绝不跟随对方 SN**——接收方据此区分"独立上报"与"对某指令的带数据应答"（readme.md §3）。
5. **去重**：接收方维护**最近 8 个已处理 SN** 的环形缓存：
   - 收到的请求 SN 已在缓存中（重复帧）→ 只重回应答/ACK，丢弃业务数据，不重复执行；
   - 不在缓存 → 正常执行并加入缓存。
6. **回绕安全**：SN 到 `0xFFF0` 后回绕到 `0x0000`。判断"新帧"不做简单大小比较，采用"**不在最近已处理集合**"或"距上次 SN 前进量 < 0x8000"的窗口算法（readme.md §4.4）。
7. **上行同样等应答**：任一方向的重要上报同样等对端确认（同 CMD 或 0x00 帧），超时同 SN 重发 ≤ 2 次（readme.md §5.5）。
8. **冲突处理（全双工交叉）**：一方正在等应答时收到对方新请求 → **先立即应答对方**（CMD 一致、SN=对方请求 SN），继续等自己的应答；收到"CMD 一致但 SN 不同"的帧按新请求处理。

## 6. 交互流程

### 6.1 正常流程（控制类，同 CMD 应答）

```
模组                                          MCU
 |---- CMD=0x10, SN=N, Payload=On -------->|
 |<--- CMD=0x10, SN=N, Payload=结果 -------|    （SN 回显）
```

### 6.2 超时重发

```
模组                                          MCU
 |---- CMD=0x10, SN=N ------------------X  (帧丢失/CRC错被丢弃)
 |        T_ACK_TIMEOUT(500ms) 超时
 |---- CMD=0x10, SN=N (原帧重发) ------->|
 |<--- CMD=0x10, SN=N -------------------|
```

### 6.3 主动上报（0x00 确认帧）

```
MCU                                           模组
 |---- CMD=0x50, SN=MCU_TX_SN++ -------->|
 |<--- CMD=0x00, SN=回显, Payload=0x00 ---|    （ACK）
```

### 6.4 双方同时发送（全双工交叉）

```
模组                                          MCU
 |---- CMD=0x10, SN=N ------------------>|
 |<---- CMD=0x40, SN=M ------------------|     （MCU 同时上报按键事件）
 |<---- CMD=0x10, SN=N ------------------|     （MCU 先立即应答模组请求）
 |---- CMD=0x00, SN=M, Payload=0x00 ---->|     （模组确认 MCU 上报）
 |<---- CMD=0x10, SN=N ------------------|     （模组继续等自己的应答，超时则重发）
```

| CMD | 名称 | 方向 | Len | Payload | 应答 |

| 0x00 | 通用确认帧 | 双向 | 1 | 状态码（§4.2） | — |

| 0x02 | 网络状态上报 | Ma2M | 1 | 0x00 未配网 / 0x01 在网 / 0x02 网络异常 / 0x03 配网中 | MCU 回 0x00 ACK |

### 8.2 电源与错误

| CMD | 名称 | 方向 | Len | Payload | 应答 |
| --- | --- | --- | --- | --- | --- |
| 0x06 | 电池电量上报 | M2Ma | 1 | 0~100（%） | 0x00 ACK |
| 0x07 | 充电状态上报 | M2Ma | 1 | 0 未知 / 1 充电中 / 2 已充满 / 3 未充电 | 0x00 ACK |
| 0x08 | 低电量报警 | M2Ma | 1 | 0 正常 / 1 警告(Warning) / 2 严重(Critical) | 0x00 ACK |

### 8.3 开关 / 亮度（Matter OnOff 0x0006、LevelControl 0x0008）

| CMD | 名称 | 方向 | Len | Payload | 应答 |
| --- | --- | --- | --- | --- | --- |
| 0x10 | OnOff 控制 | Ma2M | 1 | 0x00 Off / 0x01 On / 0x02 Toggle（Toggle 由 MCU 按当前状态翻转） | MCU 同 CMD 应答，1B：当前 OnOff（0/1），0xFF 执行失败 |
| 0x11 | 亮度控制 | Ma2M | 2 | `[0]` Level 1~100（%，0 不允许，关灯用 OnOff Off）+ `[1]` 过渡时间 ×100 ms（0=立即） | MCU 同 CMD 应答，1B：0x00 成功 / 0x01 失败 |
| 0x12 | 亮度状态 | M2Ma 上报 | 1 | 0~100（%） | 0x00 ACK |
| 0x12 | 亮度状态查询 | Ma2M | 0 | — | MCU 同 CMD 应答，1B：0~100 |

> 亮度语义：亮度 0~100% 与 Matter currentLevel（0~254）由模组线性换算；渐变到达目标值后 MCU 应以 0x12 上报最终值。

### 8.4 灯类颜色（Matter ColorControl 0x0300）

| CMD | 名称 | 方向 | Len | Payload | 应答 |
| --- | --- | --- | --- | --- | --- |
| 0x20 | 色温 CT 控制 | Ma2M | 3 | `[0-1]` ColorTemperatureMireds，0x0064~0x03E8（100~1000 mired，大端）+ `[2]` 过渡时间 ×100 ms | MCU 同 CMD 应答，1B：0x00 成功 / 0x01 失败 |
| 0x20 | CT 状态 | M2Ma 上报 | 2 | 当前 Mireds（大端） | 0x00 ACK |
| 0x20 | CT 状态查询 | Ma2M | 0 | — | MCU 同 CMD 应答，2B：当前 Mireds |
| 0x21 | 增强 Hue/Sat 控制 | Ma2M | 4 | `[0-1]` EnhancedHue 0~65535 + `[2]` Saturation 0~254 + `[3]` 过渡时间 ×100 ms | MCU 同 CMD 应答，1B：0x00/0x01 |
| 0x21 | HS 状态 | M2Ma 上报 / Ma2M 查询(0) | 3 | EnhancedHue(2B) + Saturation(1B) | 上报→0x00 ACK；查询→同 CMD 应答 |
| 0x22 | XY 控制（扩展颜色） | Ma2M | 5 | `[0-1]` X + `[2-3]` Y（各 0~65279，Matter CIE1931 编码）+ `[4]` 过渡时间 ×100 ms | MCU 同 CMD 应答，1B：0x00/0x01 |
| 0x22 | XY 状态 | M2Ma 上报 / Ma2M 查询(0) | 4 | X(2B) + Y(2B) | 上报→0x00 ACK；查询→同 CMD 应答 |
| 0x23 | 灯模式切换 | Ma2M | 1 | 0x00 白光模式(CT) / 0x01 彩光模式(HS/XY) | MCU 同 CMD 应答，1B：0x00/0x01 |
| 0x24 | Move/Stop（长按调光） | Ma2M | 2 | `[0]` 0x00 Up / 0x01 Down / 0x02 Stop + `[1]` Rate（steps/s） | MCU 同 CMD 应答，1B：0x00/0x01 |

**状态同步原则**：任何控制成功执行后，MCU 必须以对应"状态上报"CMD 主动上报当前值；**MCU 上电后应完整上报一次所有支持的属性**；模组重启后应逐项查询（对应状态查询方向）。应答帧回显请求 SN；主动上报帧用 MCU 自己的计数器。

| 0x53 | 占空上报 | M2Ma 上报 / Ma2M 查询(0) | 1 | 0 无人 / 1 占用 | 同上 |
| 0x54 | 门窗磁上报 | M2Ma 上报 / Ma2M 查询(0) | 1 | 0 关闭 / 1 打开 | 同上 |
| 0x55 | 传感器上报配置 | Ma2M | 6 | `[0]` 类型（0x00 温度 / 0x01 湿度 / 0x02 光照 / 0x03 占空 / 0x04 门窗磁）+ `[1]` 最小上报间隔 ×100 ms + `[2-3]` 最大上报间隔 ×1 s（兜底死线）+ `[4-5]` 变化阈值（按类型缩放，0=变化即报） | MCU 同 CMD 应答，1B：0x00/0x01 |
| 0x56 | 批量上报 | M2Ma | N | TLV 串联：`Type(1B) + Len(1B) + Value(nB)`（Type 取值同 0x55，Value 同各上报指令 Payload），一次携带多传感器数据 | 0x00 ACK |

**节流策略（低功耗关键）**：

- **阈值上报**：变化超过 0x55 配置阈值才上报（默认建议：温度 ≥0.5 ℃、湿度 ≥3 %RH、光照 ≥10 %）；
- **兜底上报**：即使无变化，每个最大上报间隔必须上报一次（证明在线、防状态漂移）；
- **批量合并**：多传感器同周期到期时合并进一帧 0x56，减少唤醒次数；
- 新增传感器类型（CO2、PM2.5、水浸、烟雾等）优先扩展 0x56 的 Type 枚举，不新增 CMD。

### 8.8 MCU OTA（沿用 s.md V1.06：DFU 在 Matter OTA 期间进行）

| CMD | 名称 | 方向 | Len | Payload | 应答 |
| --- | --- | --- | --- | --- | --- |
| 0xE0 | MCU 固件信息查询 | Ma2M | 0 | — | M2Ma 同 CMD，JSON：`{"p":"BK001","v":"1.0.1"}` |
| 0xE1 | OTA 通知 | Ma2M | 12 | `[0-1]` pid（大端）+ `[2-6]` 新版本 ASCII（5B）+ `[7-10]` 固件大小（4B 大端）+ `[11]` 固件累加和（从固件首字节累加取低 8 位） | MCU 同 CMD 应答，1B：0x00 接受 / 0x01 拒绝 |
| 0xE2 | 固件内容请求（拉模式） | M2Ma | 5 | `[0-3]` Offset（4B 大端）+ `[4]` Length（≤243，受 LEN≤247 约束） | Ma2M 同 CMD 应答，`[0-3]` Offset + `[4-243]` 固件数据 |
| 0xE3 | 升级结果上报 | M2Ma | 1 | 0x00 成功 / 0x01 失败 | 0x00 ACK |

**OTA 流程**（模组从 Matter OTA Provider 下载自身镜像后，向 MCU 转发 MCU 固件）：

```
模组                                          MCU
 |---- 0xE0 查询当前版本 ------------------>|
 |<--- 0xE0 {"p","v"} ----------------------|    （与 0xE1 版本比对，相同则结束）
 |---- 0xE1 新固件信息(pid/ver/size/sum) --->|
 |<--- 0xE1 0x00 接受 ----------------------|    （MCU 擦除 Flash 后应答）
 |<--- 0xE2 [Offset=0, Len=240] ------------|    （MCU 循环拉取）
 |---- 0xE2 [Offset, 数据] ---------------->|
 |              ...                         |
 |<--- 0xE3 0x00/0x01 升级结果 --------------|
 |---- 0x00 ACK ----------------------------|
```

> OTA 期间约定：暂停传感器周期上报；T_ACK_TIMEOUT 临时放宽至 1000 ms；MCU 收满 size 字节后按累加和与大小整包校验，再切镜像、上电报 0xE3；升级结果帧 SN 用 MCU 计数器正常递增。

## 9. 低功耗设计清单（模组与 MCU 共同遵守）

1. **引脚空闲高电平**；模组发包前拉低 Wakeup 2 ms，MCU 发包前 3×0x00 前导码。
2. **事件驱动，无周期心跳**：双方均不做周期性轮询；在线检测用 0x01 / 0x03 查询，传感器保底用最大上报间隔（0x55）。
3. **上报合并**：多传感器同周期数据用 0x56 批量帧一次携带。
4. **MCU 自由休眠**：无需向模组申请许可；模组下行前按 §2.3 时序唤醒。通信空闲期 MCU 可关闭 UART 外设，发送前重新初始化。
5. **参数缺省**：T_ACK_TIMEOUT=500 ms、N_RETRY=2（共 3 次）。
6. **电量联动**：电量 ≤ Warning（0x08=1）→ 上报间隔加倍、禁用 0x24 连续调光；≤ Critical（0x08=2）→ 拒绝电机/射频重操作（窗帘运动指令回失败、NACK 0x05），仅保留本地按键与低电上报。
7. **帧长最小化**：低功耗设备可不实现 0x21/0x22 彩光命令（编译裁剪），未知 CMD 回 0x00 帧状态码 0x02。

## 10. 示例报文

以下示例 CRC8 均为按 §3.1 算法计算的真实值。MCU→模组实际发送时帧前需加 `00 00 00` 前导码（下例省略）。

### 10.1 开灯（Ma2M 0x10，SN=0x0005，Payload 0x01=On）及其应答

```
模组→MCU:  55 AA 01 00 05 10 01 01 FE
MCU→模组:  55 AA 01 00 05 10 01 01 FE   （同 CMD，SN 回显，Payload=当前 OnOff=1）
```

### 10.2 亮度控制 50%、过渡 500ms（Ma2M 0x11，SN=0x0006）及应答

```
模组→MCU:  55 AA 01 00 06 11 02 32 05 24     （Level=0x32=50%，Time=0x05×100ms）
MCU→模组:  55 AA 01 00 06 11 01 00 A8        （应答：成功）
（渐变完成后 MCU 以 0x12 上报最终亮度，SN 用 MCU 自己的计数器）
```

### 10.3 温度上报 25.36℃（M2Ma 0x50，SN=0x0012）及 ACK

```
MCU→模组:  55 AA 01 00 12 50 02 09 E8 F7     （int16 大端 0x09E8 = 2536 = 25.36℃）
模组→MCU:  55 AA 01 00 12 00 01 00 5E        （0x00 确认帧，SN 回显，状态=ACK）
```

### 10.4 窗帘位置 100%（Ma2M 0x31，SN=0x0008）及应答

```
模组→MCU:  55 AA 01 00 08 31 01 64 14
MCU→模组:  55 AA 01 00 08 31 01 00 2F
```

### 10.5 OTA 数据请求 Offset=0x1000、Len=240（M2Ma 0xE2，SN=0x00A0）及数据应答

```
MCU→模组:  55 AA 01 00 A0 E2 05 00 00 10 00 F0 F7     （Offset=0x00001000，Len=0xF0）
```

**落地建议（给实现者）**：

1. 先实现骨架：帧收发状态机 + CRC8 + SN 去重 + 同 CMD 应答（约 300 行 C）。
2. 第二阶段：0x00 确认帧、0x56 批量帧、0x55 配置；OTA 最后。
3. 单元测试四个重点场景：SN 回绕（0xFFF0→0）、重发去重（重复 SN 只重回应答不执行）、CRC 错误静默丢弃、全双工交叉（§6.4）——最容易出 bug。
