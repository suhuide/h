## 第五章 协议数据包格式

数据包包括Header，Payload和Checksum格式如下：

| Packet | | | | | | | | | |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Header | | | | | | Payload | | | |
| 协议头 | 版本 | cmd(opcode) | | PacketLength | 应答标志 | 包头校验 | 可变包体（参数或数据） | 校验位 | |
| 1Byte | 1Byte | OGF(1Byte) | OCF(1Byte) | 2 Byte | 1Byte | 1Byte | 0-2048Bytes | 4Byte | |
| 0x5A | 1xxxx | 低字节 | 高字节 | 0/1 | crc8 | 数据1 | 数据2 | | |

### 5.1 Header

| 名称 | 说明 |
| --- | --- |
| 协议头 | 0x5A 用于 M001 心电贴产品 BLE 和 UART 协议 |
| 版本 | 协议版本 1.0 |
| CMD | OGF组命令指令码 + OCF子命令指令码 |
| Packetlength | 数据包总长度 |
| 应答标志 | 0: 无须等待应答; 1: 等待应答 |
| 包头校验 | 包头部分即前 7 个字节数据 CRC(POLY:07, SEED:00)校验 |

### 5.2 Payload

长度可变，长度范围为0- 2048Bytes。

### 5.3 Checksum

CRC32, POLY: 04C11DB7, SEED: FFFFFFFF

## 第六章 协议应用说明

### 6.1 指令分类

此协议根据应用场景，将指令分为两大类，一类是一般指令，主要是功能性指令，如蓝牙绑定，解绑，检测开始，停止等，以及携带数据较少的指令，即通过一个数据包可完成；另一类是分包指令，适应大数据传输，需拆分成多个数据包发送多条指令才能完成。对于分包数据发送，格式如下：分包指令遵循协议数据包格式。

※分包指令，暂无长包数据需求，未实现。

### 6.2 安全机制

1. 应答机制，每个指令结束，根据协议头来决定是否需要回复 ACK(指令)/NACK(指令)。
2. 超时机制，每个指令结束，(在需要回复的情况下)倘若超过设定时间，没有收到响应，则视为超时。可根据实际情况确定超时时间，一般为 2- 5 秒。
3. 重发机制，若某个指令超时，则重发，最多不超过次，超过 3 次，则退出本次指令。

※2，3 项未实现，应由手机/PC 端 App 把控。

- **Tx (SN write):**
  `5A02FA07 1C 00 01 7E 00 11 22 33 44 55 66 77 88 99 AA BB CC DD EE FF A6 97 67`
  `5A 02 7E 00 0F 00 00 1C FA 07 00 39 04 97 D6`
- **Rx (SN write response):**
  `5A 02 FB 07 1D 00 00 70 00 00 11 22 33 44 55 66 77 88 99 AA BB CC DD EE FF 1B 18 0E 33`
- **Tx (SN Read):**
  `5A 02 FA 08 0C 00 01 0E 0E F3 57 06`
- **Rx (Ack for SN read):**
  `5A 02 7E 00 0F 00 00 1C FA 08 00 F6 18 0F 51`

  `5A 02 FB 08 1C 00 00 C9 00 11 22 33 44 55 66 77 88 99 AA BB CC DD EE FF 8D D6 E4 C0`
