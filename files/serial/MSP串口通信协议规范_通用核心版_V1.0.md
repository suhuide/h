# MSP 串口通信协议规范（通用核心版）

## 1. 物理层与低功耗唤醒

### 1.1 串口物理参数

| 项目 | 参数 |
| --- | --- |
| 波特率 | 9600 bps |
| 数据格式 | 8N1（8 位数据位，无校验，1 位停止位） |
| 流控 | 无 |
| 字节序 | 大端（Big-Endian，高字节在前） |
| **断帧超时** | **字节间空闲超时（gap）**。帧内字节连续，若 **20 ms** 内未收到下一个字节，判定断帧，清空缓冲并寻找帧头。 |
| **帧间隔** | 收到对方 ACK 应答后，可立即发下一帧。无 ACK 的主动上报，间隔建议 ≥ 20 ms。 |

### 1.2 低功耗唤醒机制

- **Matter 唤醒 MCU**：Matter 发数据前，拉低 Wakeup 引脚保持 **5 ms** 唤醒 MCU，再发数据。
- **MCU 唤醒 Matter**：MCU 发数据前，先发送 3 个 `0x00` 作为前导码，再发送正式数据帧。

## 2. 协议帧结构

所有消息（业务控制、系统配置）均共用一套物理帧结构：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| **帧头** | 2 B | 固定 `0x55 0xAA` |
| **SN** | 1 B | 序列号（0~255 循环）。发送方递增，应答方回显。 |
| **Type** | 1 B | 消息类型（见第 3 节） |
| **Len** | 1 B | **Payload** 的字节数（不包含帧头及帧尾） |
| **Payload** | N B | 业务数据区（最大 247 字节） |
| **CRC16** | 2 B | 覆盖范围：从 `SN` 到 `Payload` 末尾 |

**校验算法：**

- 固定使用 **CRC-16/CCITT-FALSE**（Poly 0x1021，Init 0xFFFF，无反转）。
- 计算范围：不包含帧头 `55 AA`，不包含 `CRC16` 自身。
- 标准测试：字符串 `"123456789"` 算出的 CRC 应为 `0x29B1`。

**帧接收状态机：**

- 全包总长度 = **`Len + 7`** 字节。
- 找 `55 AA` → 收 3 字节（SN+Type+Len）→ 收 `Len` 字节 → 收 2 字节 CRC16。

---

## 3. 消息类型与 Payload 结构

根据 `Type` 的不同，Payload 结构如下：

| Type | 帧类型 | 方向 | 说明 |
| --- | --- | --- | --- |
| `0x01` | **CMD** | 模块 ➔ MCU | 业务控制/查询 |
| `0x02` | **ACK** | MCU ➔ 模块 | 对 CMD 的应答 |
| `0x03` | **EVENT** | MCU ➔ 模块 | 业务状态主动上报 |
| `0x04` | **ACK_EVT** | 模块 ➔ MCU | 对 EVENT 的确认 |
| `0x05` | **SYS_CMD** | 双向 | 系统级配置/OTA 请求 |
| `0x06` | **SYS_ACK** | 双向 | 系统级配置/OTA 应答 |

### 3.1 业务帧 Payload（Type 01/02/03/04）

用于设备的具体功能控制（如开关、调光、上报温度等），由各品类子规范定义。

| 帧类型 | Payload 结构 | 长度 (Len) | 说明 |
| --- | --- | --- | --- |
| CMD / EVENT | `Channel(1) + DevType(1) + Opcode(1) + Data(N)` | **3 + N** | 发起控制或上报 |
| ACK 纯确认 | 无 | **0** | 执行成功，无数据返回 |
| ACK 合一应答 | `Channel(1) + DevType(1) + Opcode(1) + Status(1) + Data(N)` | **4 + N** | 执行成功，附带当前值 |
| ACK 错误应答 | `Channel(1) + DevType(1) + Opcode(1) + Status(1)` | **4** | 执行失败，附带错误码 |
| ACK_EVT | 无 | **0** | 模块对 MCU 上报的确认 |

- `Status` 错误码：`0x00` 成功，`0x01` 不支持，`0x02` 越界，`0x03` 忙，`0x04` 故障。

### 3.2 系统帧 Payload（Type 05/06）

用于链路管理、系统配置与固件升级。

| 帧类型 | Payload 结构 | 长度 (Len) | 说明 |
| --- | --- | --- | --- |
| SYS_CMD 请求 | `Cmd(1) + Data(N)` | **1 + N** | 发起系统指令 |
| SYS_ACK 应答 | `Cmd(1) + Status(1) + Data(N)` | **2 + N** | 系统指令应答（Status=0 成功） |

---

## 4. 通用配置命令字典（SYS_CMD）

所有系统级操作均通过 `Type=0x05/0x06` 交互，Payload 首字节为 `Cmd`。

| Cmd | 功能名称 | 方向 | 请求 Data (Type=05) | 应答 Data (Type=06，成功时) | 备注 |
| --- | --- | --- | --- | --- | --- |
| `0x01` | 查版本 | 双向 | 无 | 变长 ASCII 字符串 | 如 `"BK001_1.0.1"` |
| `0x02` | 网络状态上报 | 模块 ➔ MCU | `1B`（0 未配网/1 在网/2 异常/3 配网中） | 无 | 模块状态变化时主动通知 |
| `0x03` | 恢复出厂设置 | 模块 ➔ MCU | 无 | 无 | MCU 清除本地配置，恢复默认状态 |
| `0x04` | 通道能力上报 | MCU ➔ 模块 | `Ch(1B)+DevType(1B)` 循环 | 无 | MCU 上电时主动上报自身硬件清单 |
| `0xE0` | OTA 握手 | 模块 ➔ MCU | `版本Len(1)+版本串 + 总大小(4) + 镜像CRC(2)` | 无 | MCU 回纯确认表示同意升级 |
| `0xE1` | OTA 拉数据 | MCU ➔ 模块 | `Offset(4B) + 请求长度(1B)` | `固件数据(N B)` 最大 128B | MCU 主动逐包拉取固件 |
| `0xE2` | OTA 升级结果 | MCU ➔ 模块 | `1B`（0 成功/1 失败） | 无 | 升级完成后主动上报 |

## 5. 通信机制与可靠性

1. **超时与重发**：发送请求（Type 01/03/05）后，必须在 **500 ms** 内收到对应应答。超时则以相同 SN 重发，最多重发 2 次（共 3 次）。
2. **去重防误**：接收方维护最近 8 个已处理的 SN 缓存。重复 SN 只回应答，不重复执行动作。
3. **无周期心跳**：不设周期心跳，依靠“业务超时重发”和“上电交互”作为链路存活监测。
4. **上电交互流程**：
   - MCU 上电后，发送 `SYS_CMD 0x04` 上报硬件通道清单。
   - MCU 紧接着发 `EVENT` 全量上报所有通道的初始状态。
   - 模块就绪后，发送 `SYS_CMD 0x01` 查询 MCU 版本，确认链路畅通。

## 6. 报文结构示例

*（注：以下示例的 CRC 仅作占位 `CRC_H CRC_L`，实际联调请用 CCITT-FALSE 算法计算）*

**示例 1：查版本（请求与应答）**

- 请求：`55 AA | 01 | 05 | 01 | 01 | CRC_H CRC_L` *（SN=1，SYS_CMD，Cmd=1）*
- 应答：`55 AA | 01 | 06 | 0C | 01 00 42 4B 30 30 31 | CRC_H CRC_L` *（SN=1，SYS_ACK，Cmd=1，Status=0，Data="BK001"）*

**示例 2：网络状态上报（模块通知 MCU）**

- 通知：`55 AA | 02 | 05 | 02 | 02 01 | CRC_H CRC_L` *（SN=2，SYS_CMD，Cmd=2，Data=1 在网）*
- 确认：`55 AA | 02 | 06 | 02 | 02 00 | CRC_H CRC_L` *（SN=2，SYS_ACK，Cmd=2，Status=0）*

**示例 3：MCU 上电上报通道能力**

- 上报：`55 AA | 03 | 05 | 04 | 04 01 01 02 0A | CRC_H CRC_L` *（Cmd=4，Ch1=灯，Ch2=插座）*

**示例 4：MCU 拉取 OTA 数据**

- 请求：`55 AA | 04 | 05 | 05 | E1 00 00 10 00 80 | CRC_H CRC_L` *（Cmd=E1，Offset=0x1000，Len=128）*
- 应答：`55 AA | 04 | 06 | 82 | E1 00 [128B数据] | CRC_H CRC_L` *（Cmd=E1，Status=0）*

## 7. 开发对接备忘

1. **收包解析**：找 `55 AA`，读取 `Len`，收满 `Len+5` 个字节（SN+Type+Len+Payload+CRC16），校验 CRC 后按 `Type` 分发。
2. **高低字节**：SN、Data 中的多字节数值（如 uint16/uint32/Offset/Size）、CRC16，全部遵循**高字节在前**。
3. **⚠️ 结构体警告**：在小端 MCU（如 Cortex-M）上，**禁止直接将 C 语言结构体通过 DMA 强转发送**。必须手动实现 `uint16_t` / `uint32_t` 的大端打包与解包（`buf[0]=(val>>8); buf[1]=val;`）。
