# Matter 通用串口协议

> 文档版本：V0.01
>
> **适用设备**：灯(OnOff/ Dimmable/ CT/ Extended Color)、窗帘(Window Covering)。  
> 开关(OnOff Switch/ 场景按键开关)、传感器(温湿度/ 光照/ 占空等)。    
>

---

## 1. 设计原则

1. **一帧一事务**：每条指令由序列号(SN)唯一确定，重发不改变 SN。
2. **按请求应答**：所有命令帧(查询/控制/上报)一律回**与请求同标识的应答帧**——通用帧同 Config，数据帧同 Endpoint/Cid/Aid；
    - 成功=LEN=0 确认(无 Payload)；仅查询应答携带数据(LEN≥1)。失败=不应答，由发送方超时兜底。
    - 帧内设 1 字节 **Flag**(帧头 `55 AA` + SN(2B) 之后，bit0~bit3 已定义：帧类/方向/主动应答/ACK，取值见帧格式章)。
3. **CRC8 校验**：失败帧直接丢弃、不回ACK，由发送方判断是否要超时重发。
4. **低功耗优先**：MCU 无事件即可休眠，Matter发包前先唤醒。
5. **字节序**：**大端**，全帧统一。
    - SN 高字节在前；Payload 内多字节数值高字节在前。
    - Flag/Config/LEN/CRC8 均为单字节，无字节序问题。
6. **多实例**：设备多实例覆盖。
7. **扩展性**：Config 与 Cluster 空间分区预留。

>大端（Big-Endian, BE）：高字节在前，低字节在后。0x1234 → 内存/线上顺序 12 34。  
```c
buf[0] = (uint16_t)val >> 8;buf[1] = (uint16_t)val & 0xFF;  //Tx, H go first
uint16_t val = ((uint16_t)buf[0] << 8) | buf[1];            //Rx
```
>小端（Little-Endian, LE）：低字节在前，高字节在后。0x1234 → 内存/线上顺序 34 12。  
```c
buf[0] = (uint16_t)val & 0xFF; buf[1] = (uint16_t)val >> 8; //Tx, L go first
uint16_t val = buf[0] | ((uint16_t)buf[1] << 8);            //Rx
```

## 2. 物理层与低功耗接口

### 2.1 UART

| 项目 | 参数 |
| --- | --- |
| 波特率 | 9600 bps |
| 格式 | 8N1，无流控 |
| 电平 | 与Matter VCC 供电电平一致 |
| 帧间隔 | 相邻两帧之间 ≥ 50 ms |
| 字节序 | 大端 |

### 2.2 硬件连接

| Matter | 连接方向 | MCU 主控 |
| --- | --- | --- |
| Wakeup(PXx) | → | Wakeup(Interrupt GPIO) |
| Uart Tx(PXx) | → | MCU Rx |
| Uart Rx(PXx) | ← | MCU Tx |

### 2.3 唤醒时序

- **Matter → MCU**：发送数据前，Matter先拉低 Wakeup 引脚保持 **2 ms**，再发送数据帧。
- **MCU → Matter**：数据帧前先发送 **3 个 0x00 前导码**，再发送数据帧(供Matter从低功耗状态恢复)。
- **空闲态**：TX / RX / Wakeup 三线均保持**高电平**。
- **休眠模型**：MCU 可随时休眠；Matter发数据需先唤醒 MCU。Matter自身休眠/侦听策略由Matter内部管理。

- **SN**：发送方独立计数器，超出 0xFFF0 回绕到 0。
    - 0xFFF1~0xFFFF 为保留值(将来可能作特殊帧扩展)，不作普通事务 SN。
    - 命令帧用发送方自己的计数器；应答帧回显被应答帧的 SN。
- **通用帧 Config**：命令编号(0x01~0x05、0xE0~0xE3，见通用指令表)。
- **数据帧 Value**：固定 2 字节，承载属性当前值/目标值(映射表见数据指令表)。
- **CRC8**：对 **SN 起至 PDU 末字节**计算，覆盖 SN、Flag 与全部 PDU 字段；
    - 不含帧头 `55 AA` 与 CRC 自身(Flag 决定帧性质，必须纳入校验)。通用帧/数据帧同一算法。

### 3.3 CRC8

- **算法**：CRC-8，POLY=`0x07`，INIT/SEED=`0x00`，无输入输出反射，无异或输出。
- **计算范围**：**SN 起至 PDU 最后一字节**(不含帧头、CRC 本身；
    - Flag 决定帧性质，必须纳入校验)。

```c
uint8_t crc8(const uint8_t *data, uint16_t len)
{
    uint8_t crc = 0x00;                    /* SEED */
    while (len--) {
        crc ^= *data++;
        for (uint8_t i = 0; i < 8; i++)
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
    }
    return crc;
}
/* data = 帧内从 SN 起(偏移 2)到 PDU 末字节；frame[0..1] = 55 AA
   通用帧: crc8(&frame[2], 5 + LEN);   数据帧: crc8(&frame[2], 10) */
```

> **CRC 失败处理**：接收方**静默丢弃**，不回 ACK/NACK；发送方超时后按需以**同一 SN** 重发。

### 3.4 帧接收状态机要点

1. 同步搜索 `55 AA` → 按 LEN 收满 Payload → 校验 CRC8 → 按应答标志分类。
2. LEN 上限 247，超限或帧间隔超时(建议 ≥ 100 ms 无后续字节判定帧尾失败)即丢弃重同步。
3. 前导码 `00 00 00` 由接收方在帧同步搜索中自然跳过，无需特殊处理；通用帧与数据帧共用此前导码(参考协议的 `FE` 前缀不采用)。

## 4. 应答机制

### 4.1 通用帧应答(Config 应答)

- **命令帧(Flag=0x0C Matter→MCU / 0x0E MCU→Matter)**：接收方**必须回同 Config 应答帧**(Flag=0x02 / 0x00，SN 回显)。
- **应答帧(Flag=0x02 / 0x00)**：SN 回显被应答命令帧 SN，**不再触发应答**；接收方按 SN 匹配本端挂起事务，无匹配则静默丢弃。

**应答帧 Payload(合一应答，收到即事务完成)**

- **LEN=0**：确认(ACK)——控制与上报类命令的成功应答统一为此形式
- **LEN≥1**：查询类应答携带数据(按通用指令表定义)

### 4.2 数据帧应答(Endpoint/Cid/Aid 应答)

- **控制/查询(Flag=0x0D)**：MCU 执行后回同 Endpoint/Cid/Aid、Flag=**0x03**、SN 回显、**Value=当前值**(合一应答)。
- **上报(Flag=0x0F)**：Matter 回同 Endpoint/Cid/Aid、Flag=**0x01**、SN 回显、**Value=回显上报值**(ACK)。
- CRC 失败静默丢弃；数据帧丢帧由后续上报/状态同步兜底。

### 4.3 超时与重发(仅通用帧)

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| T_ACK_TIMEOUT | **500 ms**(9600 bps 下 247 B 单帧线上耗时约 257 ms，故不得低于 300 ms) | 可通过 0x05 配置，范围 200~2000 ms，掉电不保存 |
| N_RETRY | 2(含首发共 3 次) | 超限放弃本帧并向上层报错 |
| 重发内容 | 原 SN、原 Payload，与首发**完全一致** | **SN 不可递加** |

## 5. SN(序列号)与重发规则

1. **独立计数**：Matter维护 `MATTER_TX_SN`，MCU 维护 `MCU_TX_SN`；
    - 各自从 `0x0000` 递增，互不跟随、不共用空间。
2. **重发不加 SN**：首次发送 SN=N，超时重发仍为 N；仅发送**全新事务**时计数器 +1。
3. **回显应答**：应答帧(Flag bit2=0)SN = 被应答命令帧 SN；
    - 发送方收到"应答帧且 SN 与挂起事务一致"即认为发送成功，停止重发。
4. **主动上报的 SN**：上报方(Matter或 MCU)使用**自己的计数器**取下一个 SN，**不跟随对方 SN**；
    - 接收方据此区分"独立上报"与"对某指令的带数据应答"。
5. **去重**：接收方维护**最近 8 个已处理 SN** 的环形缓存(仅对命令帧 Flag bit2=1)：
   - 收到的命令帧 SN 已在缓存中(重复帧)→ 只重回应答/ACK，丢弃业务数据，不重复执行；
   - 不在缓存 → 正常执行并加入缓存。
6. **回绕安全**：SN 到 `0xFFF0` 后回绕到 `0x0000`；
    - 新帧判据=**不在最近已处理 SN 集合**(命中=重复帧，未命中=新帧)，无其他比较
    - 计数周期为 0xFFF1(0xFFF1~0xFFFF 保留)
7. **上报同样等应答**：任一方向的重要上报同样等对端的应答帧(通用帧同 Config、数据帧同 Endpoint/Cid/Aid)，超时同 SN 重发 ≤ 2 次。
8. **冲突处理(全双工交叉)**：一方正在等应答时收到对方新请求 → **先立即应答对方**(请求标识一致、SN=对方请求 SN)；
    - 继续等自己的应答；
    - 收到"请求标识一致但 SN 不同"的帧按新请求处理。

## 6. 交互流程

### 6.1 通用帧:查询与应答(Config=0x01)

```c
Matter                                          MCU
 |---- Config=0x01, Flag=0x0C, SN=N --------->|
 |<--- Config=0x01, Flag=0x02, SN=N, Payload --|    (应答帧，SN 回显)
```

### 6.2 通用帧:超时重发

```c
Matter                                          MCU
 |---- Config=0x02, Flag=0x0E, SN=N -------X  (帧丢失/CRC错被丢弃)
 |        T_ACK_TIMEOUT(500ms) 超时
 |---- Config=0x02, Flag=0x0E, SN=N (原帧重发) ->|
 |<--- Config=0x02, Flag=0x02, SN=N ------------|
```

### 6.3 通用帧:主动上报(LEN=0 确认)

```c
MCU                                           Matter
 |---- Config=0x02, Flag=0x0C, SN=MA_TX_SN++ -->|
 |<--- Config=0x02, Flag=0x02, SN=回显, LEN=0 --|    (确认)
```

### 6.4 通用帧:双方同时发送

```c
Matter                                          MCU
 |---- Config=0x01, Flag=0x0C, SN=N ------->|
 |<---- Config=0x03, Flag=0x0E, SN=M ------|     (MCU 同时发起查询)
 |<---- Config=0x01, Flag=0x02, SN=N ------|     (MCU 先立即应答 Matter 请求)
 |---- Config=0x03, Flag=0x00, SN=M, LEN=0 ->|    (Matter 确认 MCU 查询)
 |<---- Config=0x01, Flag=0x02, SN=N ------|     (Matter 继续等自己的应答)
```

### 6.5 数据帧:控制与被动回值(窗帘 1 位置 50%)

```c
Matter                                          MCU
 |---- EP=01, Cid=0x0102, Aid=0x0008, Flag=0x0D, Value=50% -->|
 |<--- EP=01, Cid=0x0102, Aid=0x0008, Flag=0x03, Value=当前值 -|    (被动回值，合一应答)
```

### 6.6 数据帧:主动上报与 ACK(温度 1 上报)

```c
MCU                                           Matter
 |---- EP=01, Cid=0x0402, Aid=0x0000, Flag=0x0F, Value=25.36℃ ->|
 |<--- EP=01, Cid=0x0402, Aid=0x0000, Flag=0x01, Value=回显 ----|    (ACK)
```

## 8. 命令集

### 8.1 通用指令表(通用帧)

> **记法**：`B`=字节；`[n]`/`[n-m]`=Payload 内字节下标(从 0 起，多字节为大端)  
> **Flag 怎么读**(帧头 `55 AA` + SN(2B) 之后的 1 字节，按下表直接对照)
>
> | Flag | 位 3210 | 谁发给谁 | 帧性质 | 对方要做什么 |
> | --- | --- | --- | --- | --- |
> | **0x0C** | 1100 | Matter→MCU | 命令/查询 | MCU 回**同 Config 应答帧**(0x02) |
> | **0x0E** | 1110 | MCU→Matter | 命令/上报 | Matter 回**同 Config 应答帧**(0x00) |
> | **0x02** | 0010 | MCU→Matter | 应答(被动) | 无需再应答；SN 回显命令帧 |
> | **0x00** | 0000 | Matter→MCU | 应答/确认(被动) | 无需再应答；SN 回显 |
>
> 表中 `Y(0x0C)` 的 **Y**=命令帧(需应答)，括号内=帧内实际字节；`N(0x02)` 的 **N**=应答帧(不再应答)。  
> 例：`55 AA 00 01 0C 01 00 F9` → 0x0C = Matter 查询 MCU；MCU 回 `55 AA 00 01 02 01 00 D5`（0x02 = 应答，SN=0x0001 回显）。  
> **Config**=通用帧 PDU 首字节(命令编号)。**成功应答=LEN=0**；查询应答携带数据。无法处理的命令帧不应答，由发送方超时兜底。  

| 功能定义 | Flag | Config | 示例帧 | Payload 定义 / 备注 |
| --- | --- | --- | --- | --- |
| 查询 MCU 产品信息 | Y(0x0C) | 0x01 | `55 AA 00 01 0C 01 00 F9` | LEN=0 |
| 产品信息应答 | N(0x02) | 0x01 | `55 AA 00 01 02 01 19 7B 22 70 22 3A 22 42 4B 30 30 31 22 2C 22 76 22 3A 22 31 2E 31 2E 31 22 7D C8` | ASCII：{"p":"BK001","v":"1.1.1"} |

### 8.2 数据指令表(数据帧，13 字节定长)

> **帧结构**：`55 AA | SN(2B) | Flag | Endpoint | ClusterID(2B) | AttributeID(2B) | Value(2B) | CRC8`  
> **Endpoint**=实例号(0x01 起，对齐 Matter Endpoint)；**0x00=根节点**(整机级属性，如电量)。  
> **Cid/Aid**=Matter 标准 Cluster/Attribute ID| ；**Value** 固定 2 字节。     
> **Flag 怎么读**(同一位置，数据帧专用 4 个值)：
>
> | Flag | 位 3210 | 谁发给谁 | 帧性质 | 对方要做什么 |
> | --- | --- | --- | --- | --- |
> | **0x0D** | 1101 | Matter→MCU | 控制/查询 | MCU 回**同 Endpoint/Cid/Aid 的当前值**(0x03) |
> | **0x03** | 0011 | MCU→Matter | 回值应答(被动) | 无需再应答；Value=执行后的当前值 |
> | **0x0F** | 1111 | MCU→Matter | 主动上报 | Matter 回 **ACK**(0x01，Value=回显原值) |
> | **0x01** | 0001 | Matter→MCU | ACK(被动) | 无需再应答；SN 回显上报帧 |
>
> 一句话记法：**bit0=1 都是数据帧；bit1 看方向；bit2=1 是发起方(命令/上报)，bit2=0 是应答方；bit3=1 表示要对方应答。**  
> 例：`55 AA 00 05 0D 01 01 02 00 08 00 32 A0` → 0x0D = Matter 下发控制；MCU 回 `55 AA 00 05 03 01 01 02 00 08 00 32 52`（0x03 = 回值应答，SN=0x0005 回显）。  
> **控制/查询→MCU 回同 Endpoint/Cid/Aid 的当前值(被动回值，合一应答)**；上报→对端回同 Cid/Aid 的 ACK(Value=回显)。

| 功能 | Flag | Endpoint | ClusterID | AttributeID | Value | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| OnOff(例：开) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 灯实例 | 0x0006 | 0x0000 | 00 01 | 0x0000 关 / 0x0001 开 |
| OnOff 命令(例：Toggle) | 控制 0x0D→回值 0x03 | 灯实例 | 0x0006 | 0xFC02 | 00 00 | 命令：0xFC00 Off / 0xFC01 On / 0xFC02 Toggle；Value=0x0000 |
| 亮度(例：2500=50%) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 灯实例 | 0x0008 | 0x0000 | 0C 4C | 0x0000~0x1388(0~5000) |
| CT(例：400 mireds) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 灯实例 | 0x0300 | 0x0007 | 01 90 | 0x0001~0xFEFF mireds |
| X 坐标(例：红色 x≈0.64) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 灯实例 | 0x0300 | 0x0003 | A3 D7 | x×65536；与 Y 帧配对 |
| Y 坐标(例：红色 y≈0.33) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 灯实例 | 0x0300 | 0x0004 | 54 7B | y×65536 |
| 窗帘位置(例：50%) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 窗帘实例 | 0x0102 | 0x0008 | 00 32 | 0~100(0 全关/100 全开) |
| 窗帘动作命令(例：Stop) | 控制 0x0D→回值 0x03 | 窗帘实例 | 0x0102 | 0xFC02 | 00 00 | 命令：0xFC00 UpOrOpen / 0xFC01 DownOrClose / 0xFC02 StopMotion；Value=0x0000 |
| 电量(例：50%) | 仅上报 0x0F→ACK 0x01(可查询 0x0D→应答 0x03) | 根节点(EP=0) | 0x002F | 0x000C | 00 32 | BatPercentRemaining，0~100(模组映射 Matter ×2)；整机级 |
| 低电量报警(例：警告) | 仅上报 0x0F→ACK 0x01 | 根节点(EP=0) | 0x002F | 0x000E | 00 01 | BatChargeLevel：0=OK / 1=Warning / 2=Critical |
| 充电状态(例：充电中) | 仅上报 0x0F→ACK 0x01(可查询 0x0D→应答 0x03) | 根节点(EP=0) | 0x002F | 0x001A | 00 01 | BatChargeState：0=Unknown / 1=IsCharging / 2=IsAtFullCharge / 3=IsNotCharging |
| 温度(例：25.36℃) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 传感器实例 | 0x0402 | 0x0000 | 09 E8 | int16 ×0.01 ℃ |

| 门窗磁(例：打开) | 控制/查询 0x0D→回值 0x03；上报 0x0F→ACK 0x01 | 传感器实例 | 0x0045 | 0x0000 | 00 01 | 0 关闭 / 1 打开 |

### 8.3 补充说明

- **上电交互约定**：Matter 上电后以 0x01 查询 MCU 产品信息(确认 MCU 串口就绪并获取 pid/版本)；
    - MCU 上电后主动完整上报一次所有支持属性(状态同步原则)，Matter 对上报的应答即为链路确认；
    - Matter 上电/网络状态变化后主动 0x02 上报。0x05 配置掉电不保存，恢复默认。
- **亮度语义**：Value 0x0000~0x1388(0~5000)为自定义缩放，Matter currentLevel(0~254)由 Matter 换算；
    - 渐变到达目标值后 MCU 应以 Cid=0x0008 数据帧上报最终值。
- **颜色语义**：XY ↔ HS 转换由 **Matter** 完成(控制端可能下发任一格式，MCU 只需实现其一即可)。
- **状态同步原则**：任何控制成功执行后，MCU 必须以对应 Cid/Aid 的数据帧(Flag=0x0F)主动上报当前值；
    - **MCU 上电后应完整上报一次所有支持的属性**
    - Matter 重启后应逐项查询(对应状态查询方向)。应答帧回显请求 SN
    - 主动上报帧用 MCU 自己的计数器。
    - OnOff 的 Toggle 由 MCU 翻转，翻转后必须以 Cid=0x0006 数据帧上报最终状态。
- **多实例(Endpoint)**：数据帧的 Endpoint 字节即实例号(0x01 起=第 1 实例，对齐 Matter Endpoint 编号)；
    - **Endpoint=0=根节点**，用于整机级属性(电量 0x002F/0x000C 等)；
    - 单实例产品固定填 0x01；通用帧(系统/网络/OTA)为整机级，无 Endpoint 概念；
- **帧判别**：Flag bit0 区分通用帧/数据帧，bit1 方向，bit2 主动/应答，bit3 ACK 请求；通用帧再按 Config 分类，数据帧按 Cid/Aid 分类。

**OTA 流程**(Matter 从 Matter OTA Provider 下载自身镜像后，向 MCU 转发 MCU 固件)：

```c
Matter                                          MCU
 |---- 0xE0 查询当前版本 ------------------->|
 |<--- 0xE0 {"p","v"} ----------------------|    (与 0xE1 版本比对，相同则结束)
 |---- 0xE1 新固件信息(pid/ver/size/sum) --->|
 |<--- 0xE1 确认(LEN=0) -------------------|    (MCU 擦除 Flash 后应答)
 |<--- 0xE2 [Offset=0, Len=240] ------------|    (MCU 循环拉取)
 |---- 0xE2 [Offset, 数据] ---------------->|
 |              ...                         |
 |<--- 0xE3 0x00/0x01 升级结果 --------------|
 |---- 0xE3 应答(FLAG=0, LEN=0) ------------|
```

> OTA 期间约定，暂停传感器周期上报  
> MCU 收满 size 字节后按累加和与大小整包校验，再切镜像、上电报 0xE3  
> 升级结果帧 SN 用 MCU 计数器正常递增  
> **固件数据(0xE2 Payload)按字节透传**：其内部字节序由 MCU 架构/编译器决定(如 Cortex-M 为小端)，  
> 协议不转换、两端不得做字节序变换；帧内 Offset/Length/pid/大小等协议字段仍为大端。

## 9. 示例报文

以下示例 CRC8 均为按所定义算法计算的真实值(范围=SN→PDU 末字节，通用/数据帧同)。MCU→Matter 实际发送时帧前需加 `00 00 00` 前导码(下例省略)。

### 9.1 通用帧:查询产品信息(Config=0x01)及应答

```c
Matter→MCU:  55 AA 00 05 0C 01 00 A1    (Flag=0x0C 命令帧)
MCU→Matter:  55 AA 00 05 02 01 19 7B 22 70 22 3A 22 42 4B 30 30 31 22 2C 22 76 22 3A 22 31 2E 31 2E 31 22 7D 74    (Flag=0x02 应答帧，SN 回显)
```

### 9.2 数据帧:电量上报 50%(EP=0, Cid=0x002F, Aid=0x000C)及 ACK

```c
MCU→Matter:  55 AA 00 06 0F 00 00 2F 00 0C 00 32 C0    (Flag=0x0F 上报 50%)
Matter→MCU:  55 AA 00 06 01 00 00 2F 00 0C 00 32 32    (Flag=0x01 ACK，Value=回显)
```

### 9.3 数据帧:窗帘 1 位置 50%(Endpoint=01)与被动回值

```c
Matter→MCU:  55 AA 00 05 0D 01 01 02 00 08 00 32 A0    (Flag=0x0D 控制)
MCU→Matter:  55 AA 00 05 03 01 01 02 00 08 00 32 52    (Flag=0x03 回当前值，合一应答)
```

### 9.4 数据帧:窗帘 1 命令 UpOrOpen 与 StopMotion(各一帧)

```c
Matter→MCU:  55 AA 00 06 0D 01 01 02 FC 00 00 00 0F    (Flag=0x0D，UpOrOpen 命令)
Matter→MCU:  55 AA 00 07 0D 01 01 02 FC 02 00 00 A0    (Flag=0x0D，StopMotion 命令)
```

### 9.5 数据帧:温度 1 主动上报(Flag=0x0F)与 ACK

```c
MCU→Matter:  55 AA 00 12 0F 01 04 02 00 00 09 E8 02    (Flag=0x0F 上报 25.36℃)
Matter→MCU:  55 AA 00 12 01 01 04 02 00 00 09 E8 F0    (Flag=0x01 ACK，Value=回显)
```

### 9.6 通用帧:OTA 数据拉取(Config=0xE2)与数据应答

