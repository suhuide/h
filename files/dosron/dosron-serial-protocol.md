## 1. 概述
文档主要介绍Matter Over Thread 标准串口对接协议，主要用于Matter模组与其他 MCU 端串口通信，并在附录中包含所有窗帘电机相关的上下行命令及相关属性的整理。
## 2. 硬件连接
Matter模组（TS24-U）和 MCU 端主控均采用 DC 3.3V 电压供电。Matter模组（TS24-U）与 MCU 之间 UART 通信波特率设置为 9600-8-N-1，并且无数据流控。
UART 接口引脚采用标准逻辑，在空闲状态下，TXD 和 RXD 引脚均为高电平，以低电平作为起始位，以高电平作为停止位，即使设备进入休眠状态，引脚也维持高电平。
> 注：模组发数据前，会将 PC1 拉低延迟开始发送串口数据，数据发送完成后将 PC1 拉高；MCU 发送数据之前，需要加 3 个 00 作为前导码，前导码发送之后再发送串口数据。

| 名称 | 标号 |
| ---------- | ------ |
| TX | PB0 |
| RX | PA0 |
| 模组唤醒 MCU | PC1 |
| MCU 唤醒模组 | RX 唤醒 |
## 3. 帧格式说明
通讯帧格式如下：

| Front | Ver | Seq | Cmd | Length | Data | Check |
| ------ | ---- | ------ | ------ | ---------- | ------ | -------- |
| 帧头 | 版本 | 序列号 | 命令字 | 数据长度 | 数据 | 校验和 |

| 字段 | 字节数 | 说明 |
| -------- | ------ | ---------------------------------------------------- |
| 帧头 | 2 | 固定 0x55AA |
| 版本 | 1 | 串口通信协议版本，升级扩展用 |
| 序列号 | 2 | 传输数据序列号，范围 0~0xfff0，到达 0xfff0 之后重新回到 0 |
| 命令字 | 1 | 具体帧类型，参考命令字索引 |
| 数据长度 | 2 | 传输的有效数据长度 |
| 数据 | N | 传输的有效数据 |
| 校验和 | 1 | 数据校验，从帧头开始按字节求和得出的结果对 256 求余 |

## 5. 协议详述
### 5.1 网络状态通知
**网络状态表**  
| 设备状态 ID | 描述 |
| ----------- | ------------------------------------------------ |
| 0x00 | 设备为未入网状态 |
| 0x01 | 设备为已入网状态 |
| 0x02 | 设备网络状态异常(例如未获取到窗帘相关信息) |
| 0x03 | 设备为配网中状态 |


**说明：**
- 设备未入网状态：设备第一次上电、或者入网失败、或者离网的情况下，设备状态为未入网状态，并将该状态下发至 MCU。
- 设备为已入网状态：设备入网成功之后，设备状态为已入网状态，并将该状态下发至 MCU。
- 当模组的网络状态发生变化，则主动下发模组网络状态至 MCU。  
**模组发送：**
| 字段 | 长度（byte） | 说明 |
| -------- | ------------ | ------------------------------------------ |
| 帧头 | 2 | 0x55AA |
| 版本 | 1 | 0x02 |
| 序列号 | 2 | N |
| 命令字 | 1 | 0x02 |
| 数据长度 | 2 | 0x0001 |
| 数据 | 1 | 指示模组工作状态：参见**网络状态表** |
| 校验和 | 1 | 从帧头开始按字节求和得出的结果对 256 求余 |
例：`0x55AA 02 N 02 00 01 00 XX`  
**MCU 返回：**
| 字段 | 长度（byte） | 说明 |
| -------- | ------------ | ------------------------------------------ |
| 帧头 | 2 | 0x55AA |
| 版本 | 1 | 0x02 |
| 序列号 | 2 | N |
| 命令字 | 1 | 0x02 |
| 数据长度 | 2 | 0x0000 |
| 数据 | 0 | 无 |
| 校验和 | 1 | 从帧头开始按字节求和得出的结果对 256 求余 |
例：`0x55AA 02 N 02 0000 XX`
### 5.2 模组配网或复位
**注意：**
- MCU 发送配网命令需要在收到并回复了模组查询设备能力（cmd：0x30）后。
- 为避免底层 SDK 部分网络状态未清除干净，建议每次扫描网络前先本地离网重启后发送配网命令。
| 命令 | 说明 |
| ---- | ------------------------------------------------------------ |
| 0x00 | 将模组软件复位 |
| 0x01 | 将模组配置为开始配网状态。 |
| 0x02 | 停止配网，在配网过程中发送会立即停止配网，不在配网过程发送，则无效 |
| 0x03 | 模组本地离网 |

**MCU 发送：**
| 字段 | 长度（byte） | 说明 |
| -------- | ------------ | ------------------------------------------ |
| 帧头 | 2 | 0x55AA |
| 版本 | 1 | 0x02 |
| 序列号 | 2 | N |
| 命令字 | 1 | 0x03 |
| 数据长度 | 2 | 0x0001 |
| 数据 | 1 | 0x00/0x01/0x02/0x03 |
| 校验和 | 1 | 从帧头开始按字节求和得出的结果对 256 求余 |  

**模组返回：**
| 字段 | 长度（byte） | 说明 |
| -------- | ------------ | ------------------------------------------ |
| 帧头 | 2 | 0x55AA |
| 版本 | 1 | 0x02 |
| 序列号 | 2 | N |

### 5.6 信标产测通知
如果模组周围有信标 Dongle，未配网的设备上电 500ms 之内即会进入信标产测，此时模组会通知 MCU 开始产测，该命令一般用于成品测试。
信标 Dongle 可以在 IOT 平台上采购，在搜索框中填写 2.03.02.00004 物料号，选择 Zigbee 产测信标。信标程序从生产管理系统下载：生产管理系统 > 知识库管理 > 驱动下载（包含工具和烧录固件）。使用方法参考使用文档。
