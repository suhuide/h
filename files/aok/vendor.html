1. 概述

1.1 背景

奥科的产品涉及转 CD（设备证书）交付给客户。模块在我司完成生产（烧录固件、初始 DAC、出厂信息）后，交付到客户手中时，客户需要有能力修改以下出厂定制数据：

  • VID（Vendor ID）、PID（Product ID）
  • vendor_name / product_name / product_label
  • part_number / product_url
  • CD（设备证书及其相关凭据）

1.2 目的与三大工作项

#工作项说明
1MFG_Tool 更新（JSON 配置）工具支持 JSON 配置定义待修改字段，自动完成 NVM3 读写
2DAC Server 验证服务器按新 VID/PID 生成 CD/DAC，并完成离线签名
3双重验证（外网电脑）隔离环境端到端复核全流程

1.3 核心安全原则

  1. 签名私钥（command_key.pem）永不出服务器——客户电脑只持有一次性令牌；
  2. Challenge-Response 解锁——令牌与芯片序列号 + Challenge 绑定；
  3. NVM3 修改前先备份——写入前读取完整镜像留档；
  4. 写后必读校验——写入后重新 read + parse 比对。

4. NVM3 数据布局与字段映射

4.1 NVM3 区域

  • 地址范围：0x08174000 - 0x0817E000（40960 B）
  • CD 等证书数据存放在 NVM3 的最后一个 page
  • Security mode: none（解锁后可直接读写）

4.2 关键 Key 映射表（实测）

Key长度实测内容推断字段可改
0x8720016B0ECB29B3...模块序列号否
0x872048B20260907生产日期否
0x8720a132BHBl2IFqp...CD 证书数据块随客户更换
0x8720b2B05 30VID（小端 0x3005）可改
0x8720c2B9A 14PID（小端 0x149A）可改
0x8720d4BA-OKvendor_name可改
0x8720e15BWindow C...product_name可改
0x8720f4BV1.0软件版本视需求
0x8721015BWindow C...product_label可改
0x8721122Bhttps://...product_url可改
0x8721215BWindow C...part_number可改
0x872182B01 00使能标志否
0x8721f32B6457dae0...校验哈希随内容更新
⚠️ 0x87207 / 0x87208 / 0x87318 等字段确切含义需与固件组确认后固化到 JSON 模板。
⚠️ 字符串长度限制：写入长度不得大于原 NVM3 对象长度，超长必须由工具预先拦截报错。

4.3 修改约束

  • VID/PID 为 2 字节小端 uint16；CD 由 DAC Server 生成后整体替换；
  • 按 Key 粒度执行 commander nvm3 writedevice，禁止整区擦除重写；
  • 结构体长度表（0x87220~0x87227）需在修改字符串类字段时同步更新。

5.2 MFG_Tool 功能点

#功能实现说明
F1JSON 配置加载渲染客户可编辑表单（仅 editable:true 字段）
F2自动备份写前 nvm3 read，镜像 nvm3_bk_<Serial>_<时间戳>.s37，本地+回传服务器
F3Challenge 采集后台 security gencommand，提取 Serial + Challenge
F4服务器交互HTTPS 上传 Challenge 与定制请求；接收令牌与 CD 包
F5令牌放置自动写入 SecurityStore\device_<Serial>\challenge_<Challenge>\
F6解锁执行security unlock --unlock-param 1111（须与服务器一致）
F7逐字段写入按 JSON 组装 nvm3 writedevice 命令
F8长度预校验字符串超长直接报错，保护 NVM3 结构
F9读回校验read + parse 逐字段比对，输出校验报告
F10失败回滚commander flash 备份镜像恢复

5.3 关键命令参考（实测通过）

:: 备份
commander nvm3 read -o nvm3.s37 --device efr32mg24 --range 0x8174000:0x817e000
:: 解析指定 Key（例：vendor_name = "A-OK"）
commander nvm3 parse nvm3.s37 --key 0x08720D
:: 写入（例：改为 "BK"，ASCII 42 4B）
commander nvm3 writedevice --object 0x08720D:424B --device EFR32MG24B210F1536IM48
:: 读回验证
commander nvm3 read -o nvm3-bk.s37 --device efr32mg24 --range 0x8174000:0x817e000
commander nvm3 parse nvm3-bk.s37 --key 0x08720D
✅ 实测记录（2026-09-07 样片）：0x8720d 原值 "A-OK" → 写入 "BK" → 读回确认一致，流程闭环验证通过。

6. DAC Server 端流程

6.1 职责

  1. 接收 HTTPS 请求（Serial + Challenge + 定制申请单）；
  2. 校验新 VID/PID 合法性（Matter VID 分配库）；
  3. 依据 PAA 链签发新 DAC / CD；
  4. 用 command_key.pem 对客户端 Challenge 离线签名，产出 unlock_payload_*.bin；
  5. 打包下发：令牌 + CD blob + 字段写入清单。

6.2 验证清单

#验证项通过标准
V1签名链完整令牌可被 Commander 识别并解锁实测芯片
V2参数一致性签名 unlock-param 与客户端执行值一致（1111）
V3CD 有效性attestation 格式校验通过，VID/PID 与请求一致
V4密钥隔离下发包中不含任何 .pem 私钥
V5日志审计记录 Serial、Challenge、时间、操作人、字段值

8. 安全注意事项

  1. 私钥零下发：command_key.pem / cert_key.pem 只存在于 DAC Server；
  2. HTTPS 传输：Challenge 上行、令牌下行全程加密，防令牌截获；
  3. 令牌绑定：仅对该 Serial + 该 Challenge 有效，需作废时服务器执行 rollchallenge；
  4. 审计留痕：签发日志与备份镜像保存 ≥12 个月；
  5. 权限收敛：客户仅可改 editable:true 字段；
  6. 密级控制：对外版本文档需裁剪第 4 节 NVM3 布局细节。

9. 异常处理与回滚

异常现象排查步骤回滚手段
unlock 找不到令牌检查 SecurityStore 路径 Serial/Challenge 文件夹名是否匹配重新走签名流程
解锁失败（令牌存在）核对 unlock-param；Challenge 是否被滚动重新申请签名
写入后 parse 异常字符串超长 / 长度表未同步commander flash 备份镜像恢复
设备证明失败CD 与 VID/PID 不匹配（0x8720a/0x8720b/0x8720c）恢复备份或重新定制
