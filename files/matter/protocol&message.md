# Matter 标准Protocol和Message归纳

Matter 的 Protocol 是一个抽象概念，其类型体系围绕通信分层、功能模块、交互场景设计，涵盖核心协议、应用协议、传输协议等维度，是设备互联互通的基础框架。  
每个 Protocol 都包含了多种消息类型（Message Type），这些消息类型实现了协议的具体功能。每个 Message Type 都是一个设备间交换的具体数据单元，包含了必要的控制、状态、命令和数据。

---

## 一、协议分层架构

Matter 协议基于分层设计，从底层到应用层分为：

| 层级 | 核心协议类型 | 作用 |
|------|--------------|------|
| 应用层 | 交互模型协议、集群协议 | 定义设备业务交互逻辑（如属性读写、命令调用）、功能集群规范（如开关、灯光控制） |
| 会话层 | 安全通道协议、会话管理协议 | 建立加密通信链路、管理设备间会话生命周期 |
| 传输层 | UDP、TCP、BLE、Thread、Wi-Fi | 底层数据传输载体，Matter 适配多种物理网络 |
| 基础层 | 消息编码协议、安全协议 | 处理消息序列化（CBOR）、加密（AES-CCM）、认证（PASE/CASE） |

---

## 二、核心协议类型详解

### 1. 交互模型协议（Interaction Model Protocol）

- **协议 ID**：`0x0000_0001`（通用厂商 ID）
- **核心作用**：Matter 设备业务交互的核心协议，定义了设备间属性读写、命令调用、事件上报的标准化流程。
- **关键机制**：
  - 属性交互：如读取传感器数值、设置灯光亮度
  - 命令执行：如发送“开关控制”命令、触发场景
  - 事件通知：如设备状态变化后主动上报事件（如温度超限告警）
- **应用场景**：所有设备业务功能的交互（如开关设备、调节参数）

#### 主要 Message Types：

| 消息类型 | 十六进制 ID | 描述 | 用途 |
|----------|--------------|------|------|
| StatusResponse | 0x01 | 状态响应 | 返回操作结果 |
| ReadRequest | 0x02 | 读取请求 | 请求读取属性 |
| SubscribeRequest | 0x03 | 订阅请求 | 请求订阅变化 |
| SubscribeResponse | 0x04 | 订阅响应 | 确认订阅结果 |
| ReportData | 0x05 | 数据报告 | 主动上报属性/事件 |
| WriteRequest | 0x06 | 写入请求 | 修改设备属性 |
| WriteResponse | 0x07 | 写入响应 | 确认写入结果 |
| InvokeCommandRequest | 0x08 | 命令调用请求 | 触发设备动作 |
| InvokeCommandResponse | 0x09 | 命令调用响应 | 返回命令执行结果 |
| TimedRequest | 0x0A | 定时请求 | 用于原子性写入等场景 |

---

### 2. 安全通道协议（Secure Channel Protocol）

- **协议 ID**：`0x0000_0002`
- **核心作用**：建立设备间的加密通信链路，保障数据传输的机密性和完整性。
- **关键机制**：
  - 会话建立：通过 PASE（配网阶段）或 CASE（入网后）协议协商加密密钥
  - 消息加密：采用 AES-CCM 算法加密消息，附带消息认证码（MAC）防篡改
  - 会话管理：维护会话生命周期（建立、续期、销毁）
- **应用场景**：设备配网、入网后所有加密通信（如控制指令、数据上报）

#### 主要 Message Types：

| 消息类型 | 十六进制 ID | 描述 | 用途 |
|----------|--------------|------|------|
| MsgCounterSyncReq | 0x00 | 消息计数器同步请求 | 确保双方消息顺序一致 |
| MsgCounterSyncRsp | 0x01 | 消息计数器同步响应 | 响应同步请求 |
| StandaloneAck | 0x10 | 独立确认消息 | 显式确认某条消息已接收 |
| PBKDFParamRequest | 0x20 | PBKDF 参数请求 | 交换密码派生函数参数 |
| PBKDFParamResponse | 0x21 | PBKDF 参数响应 | 返回 PBKDF 参数 |
| PASE_Pake1 | 0x22 | PASE 第一阶段 | 密码认证会话建立起始 |
| PASE_Pake2 | 0x23 | PASE 第二阶段 | 中间交换 |
| PASE_Pake3 | 0x24 | PASE 第三阶段 | 完成密钥协商 |
| CASE_Sigma1 | 0x30 | CASE 第一阶段 | 证书认证会话发起 |
| CASE_Sigma2 | 0x31 | CASE 第二阶段 | 证书与证明交换 |
| CASE_Sigma3 | 0x32 | CASE 第三阶段 | 会话密钥确认 |
| CASE_Sigma2Resume | 0x33 | CASE 恢复第二阶段 | 会话恢复优化 |
| StatusReport | 0x40 | 状态报告 | 报告错误或设备状态 |
| ICD_CheckIn | 0x50 | ICD 设备签到 | 低功耗设备定期上报 |

---

### 3. 块传输协议（Bulk Data Exchange, BDX）

- **协议 ID**：`0x0000_0003`
- **核心作用**：用于大文件/数据块传输，支持断点续传、分块传输，适配固件升级、日志传输等场景。
- **关键机制**：
  - 分块传输：将大文件拆分为固定大小的块（如 1KB），逐块传输
  - 断点续传：记录已传输块的偏移量，中断后可从断点恢复
  - 传输控制：支持暂停、继续、取消传输
- **应用场景**：设备固件升级（OTA）、批量日志上传、大型配置文件同步

#### 主要 Message Types：

| 消息类型 | 十六进制 ID | 描述 | 用途 |
|----------|--------------|------|------|
| SendInit | 0x01 | 发送初始化 | 发起数据传输 |
| SendAccept | 0x02 | 发送接受 | 接收方确认准备就绪 |
| ReceiveInit | 0x04 | 接收初始化 | 接收方主动请求 |
| ReceiveAccept | 0x05 | 接收接受 | 发送方确认 |
| BlockQuery | 0x10 | 块查询 | 请求特定数据块 |
| Block | 0x11 | 数据块 | 传输实际数据 |
| BlockEOF | 0x12 | 块结束 | 标志传输完成 |
| BlockAck | 0x13 | 块确认 | 确认收到某块 |
| BlockAckEOF | 0x14 | 块结束确认 | 确认整个传输完成 |
| BlockQueryWithSkip | 0x15 | 带跳过的块查询 | 支持断点续传 |

---

### 4. 回声测试协议（Echo Protocol）

- **协议 ID**：`0x0000_0004`
- **核心作用**：用于网络连通性测试和延迟测量（类似网络“Ping”功能）。
- **关键机制**：
  - 发送方发送回声请求（Echo Request），接收方返回回声响应（Echo Response）
  - 可携带测试数据，验证数据传输的准确性
- **应用场景**：设备入网后的链路检测、调试阶段的网络连通性验证

#### 主要 Message Types：

| 消息类型 | 十六进制 ID | 描述 | 用途 |
|----------|--------------|------|------|
| EchoRequest | 0x01 | 回声请求 | 发送测试负载 |
| EchoResponse | 0x02 | 回声响应 | 返回相同负载 |

---

### 5. 用户定向配网协议（User Directed Commissioning, UDC）

- **协议 ID**：`0x0000_0005`
- **核心作用**：简化用户引导配网流程，支持扫码配网、手动输入配网码等交互方式。
- **关键机制**：
  - 配网码解析：从二维码或手动输入的配网码中提取设备信息（如鉴别器、PIN 码）
  - 配网引导：引导用户完成网络选择、权限认证等步骤
- **应用场景**：设备首次配网时的用户交互流程（如手机 APP 扫码添加设备）

#### 主要 Message Types：

| 消息类型 | 十六进制 ID | 描述 | 用途 |
|----------|--------------|------|------|
| IdentificationDeclaration | 0x00 | 身份声明 | 设备广播自身身份和配网能力 |

---

### 6. 固件更新协议（Software Update Protocol）

- **核心作用**：管理设备固件升级流程，包括版本检查、升级包下载、安装验证。
- **关联协议**：依赖 BDX 协议传输固件包，通过交互模型协议发送升级指令。
- **应用场景**：设备远程固件升级（OTA）。

### 7. 发现协议（Discovery Protocol）

- **核心作用**：实现设备局域网发现和配网者（Commissioner）发现，支持 mDNS、BLE 广播等方式。
- **关键机制**：
  - mDNS 发现：设备入网后通过 mDNS 广播自身信息（如设备类型、Node ID）
  - BLE 发现：未入网设备通过 BLE 广播配网信息（如鉴别器、PIN 码）
- **应用场景**：配网者发现待配网设备、设备入网后被控制器发现。

---

## 三、厂商自定义协议

Matter 允许厂商扩展自定义协议，通过**厂商 ID + 协议 ID** 标识：

- **厂商 ID**：非 `VendorId::Common`（0x0000），如苹果 0x000C、谷歌 0x130A
- **协议 ID**：厂商自行分配（如 0x0001）
- **应用场景**：厂商特定功能扩展（如设备私有通信协议）

---

## 四、协议交互流程示例（配网 + 控制）

### 配网阶段：
1. 设备通过**发现协议**（BLE/mDNS）被配网者发现
2. 通过**安全通道协议**（PASE）建立加密链路，完成身份认证
3. 通过**用户定向配网协议**引导用户输入网络信息（如 Wi-Fi 密码）

### 控制阶段：
1. 控制器通过**交互模型协议**发送“开灯”命令
2. 命令通过**安全通道协议**加密传输
3. 设备执行命令后，通过**交互模型协议**返回执行结果

---

## 五、协议类型的识别与管理

Matter 通过**协议 ID（protocolId）** 和**厂商 ID（vendorId）** 唯一标识协议类型：

- **通用协议**：厂商 ID 为 `0x0000`，协议 ID 对应预定义类型
- **自定义协议**：厂商 ID 非 `0x0000`，需厂商自行解析

代码映射示例（GetProtocolName）：
- 协议 ID `0x0000_0001` → Interaction Model
- 协议 ID `0x0000_0002` → Secure Channel
- 协议 ID `0x0000_0003` → BDX
- 协议 ID `0x0000_0004` → Echo
- 协议 ID `0x0000_0005` → UDC

## 总结

Matter 协议类型围绕**互联互通、安全、易用性**设计：
- **核心协议**（交互模型、安全通道）支撑基础通信
- **扩展协议**（BDX、UDC）适配特定场景

### 6. 固件更新协议（Software Update Protocol）

- **核心作用**：管理设备固件升级流程，包括版本检查、升级包下载、安装验证。
- **关联协议**：依赖 BDX 协议传输固件包，通过交互模型协议发送升级指令。
- **应用场景**：设备远程固件升级（OTA）。

### 7. 发现协议（Discovery Protocol）

- **核心作用**：实现设备局域网发现和配网者（Commissioner）发现，支持 mDNS、BLE 广播等方式。
- **关键机制**：
  - mDNS 发现：设备入网后通过 mDNS 广播自身信息（如设备类型、Node ID）
  - BLE 发现：未入网设备通过 BLE 广播配网信息（如鉴别器、PIN 码）
- **应用场景**：配网者发现待配网设备、设备入网后被控制器发现。

---

## 三、厂商自定义协议

Matter 允许厂商扩展自定义协议，通过**厂商 ID + 协议 ID** 标识：

- **厂商 ID**：非 `VendorId::Common`（0x0000），如苹果 0x000C、谷歌 0x130A
- **协议 ID**：厂商自行分配（如 0x0001）
- **应用场景**：厂商特定功能扩展（如设备私有通信协议）

---

## 四、协议交互流程示例（配网 + 控制）

### 配网阶段：
1. 设备通过**发现协议**（BLE/mDNS）被配网者发现
2. 通过**安全通道协议**（PASE）建立加密链路，完成身份认证
3. 通过**用户定向配网协议**引导用户输入网络信息（如 Wi-Fi 密码）

### 控制阶段：
1. 控制器通过**交互模型协议**发送“开灯”命令
2. 命令通过**安全通道协议**加密传输
3. 设备执行命令后，通过**交互模型协议**返回执行结果

---

## 五、协议类型的识别与管理

Matter 通过**协议 ID（protocolId）** 和**厂商 ID（vendorId）** 唯一标识协议类型：

- **通用协议**：厂商 ID 为 `0x0000`，协议 ID 对应预定义类型
- **自定义协议**：厂商 ID 非 `0x0000`，需厂商自行解析

代码映射示例（GetProtocolName）：
- 协议 ID `0x0000_0001` → Interaction Model
- 协议 ID `0x0000_0002` → Secure Channel
- 协议 ID `0x0000_0003` → BDX
- 协议 ID `0x0000_0004` → Echo
- 协议 ID `0x0000_0005` → UDC

---

## 总结

Matter 协议类型围绕**互联互通、安全、易用性**设计：
- **核心协议**（交互模型、安全通道）支撑基础通信
- **扩展协议**（BDX、UDC）适配特定场景

理解协议类型有助于掌握 Matter 设备的通信逻辑，实现设备间的标准化交互与扩展开发。
